# Ревизия безопасности и оптимизации (перед выкаткой)

## Безопасность — что сделано
- **Пароли**: хранится только pbkdf2-хэш (200k раундов, соль). Сам пароль не хранится.
- **Сессии**: отзываемые токены со сроком; cookie `HttpOnly`, `SameSite=Lax`; за TLS —
  `Secure` (`GAME_SECURE=1`). Сервер сам проверяет сессию на каждом запросе/WS.
- **Гость только в dev**: в проде (`GAME_ENV=prod`) `/auth/guest` отказывает на сервере.
- **Анти-брутфорс**: ≤10 попыток входа с адреса за минуту.
- **WebSocket**: предел кадра 1 МБ (защита от кадра-гиганта), ping/pong/close,
  аккуратное закрытие при обрыве.
- **Не root**: контейнер крутит сервер под пользователем `app`.
- **Server-authoritative**: клиент шлёт только намерения; исход (награды, бой,
  экономика) считает сервер — клиент нельзя «уговорить» выдать лишнее.

## Безопасность — обязательно перед публичным проде
- Сменить `DB_PASSWORD`; не хранить секреты в образе — только через окружение/секреты.
- Поставить за TLS (nginx/caddy обратным прокси) и включить `GAME_SECURE=1`.
- Ограничить доступ к порту БД (в compose БД не публикуется наружу — хорошо).
- Добавить верификацию e-mail и сброс пароля (сейчас нет).
- Рассмотреть CSRF-токен для `/auth/*` (сейчас `SameSite=Lax` прикрывает основное).

## Оптимизация — что сделано
- **LoD**: детально считаются только занятые деревни; пустые — дёшево (offline),
  тела NPC выгружаются из RAM. Деревня назначения греется заранее (бесшовно).
- **Шардинг**: мир делится на шарды; передача персонажа при межшардовом пути.
- **WebSocket** вместо опроса: нет накладных HTTP на каждый тик.
- **Один тик-поток на мир**: намерения применяются по порядку, без гонок (RLock).

## Оптимизация — на вырост (при росте нагрузки)
- Пуш по изменению (dirty-флаг) и дельты вместо полного снимка каждому раз в секунду.
- `ThreadingHTTPServer` — поток на соединение: для тысяч игроков перейти на asyncio/
  epoll (один цикл на много сокетов). Сейчас норм на десятки-сотни.
- Шарды в разных процессах/узлах (сейчас в одном процессе, тикают в ногу); передача
  персонажа уже сериализуется — путь к реальному мульти-процессу готов.
- JSONB-индексы в Postgres по «горячим» полям игрока, если понадобятся выборки.
- Снимок мира — одной строкой; хронику/могилы в проде лучше отдельными строками.
