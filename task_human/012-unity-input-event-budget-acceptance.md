# 012 — Unity runtime acceptance: high-polling input devices

**Исполнитель:** владелец проекта.  
**Поддержка:** ChatGPT — исправление по F3 dump/Unity log.  
**Версия:** Unity 6000.6.7f1.  
**Ветка:** `fix/input-event-budget-unlimited-20261118`.

## Цель

Проверить на реальном устройстве, что Unity Input System больше не отбрасывает события при известном HID burst объёмом около 5.2 MiB за один update, а диагностическая строка показывает фактический лимит.

## Проверка

1. Открыть актуальную ветку в Unity 6000.6.7f1 и дождаться завершения импорта.
2. Запустить сцену и открыть developer diagnostics клавишей F3.
3. В строке физических нажатий проверить суффикс `input budget: 8 MiB`. Если в Project Settings уже намеренно выставлено `0`, ожидается `input budget: unlimited`; большее пользовательское значение должно сохраниться.
4. Оставить подключённым высокочастотное HID-устройство, которое ранее вызывало предупреждение `Exceeded budget for maximum input event throughput`. Несколько минут двигать мышь, нажимать клавиши и проверять клики/взаимодействия.
5. Убедиться, что предупреждение о превышении бюджета не повторяется, а F3 показывает ожидаемые физические клавиши и последнюю фазу Input Action.
6. Если предупреждение сохраняется или появляется самопроизвольное движение, сохранить F3 diagnostic dump и Unity Editor log. Не менять лимит на unlimited вслепую: сначала нужны реальные данные о размере событий и поведении устройства.

## Ожидаемый результат

- Минимум 8 MiB на update, если проект использует конечный лимит.
- Значение `0` (unlimited) и любой больший лимит не перезаписываются.
- События клавиатуры/мыши не теряются из-за прежнего 5 MiB порога.

Это не заменяет профилирование main-thread stalls и не доказывает, что любое самопроизвольное движение вызвано лимитом событий. CI проверяет чистую политику; Unity runtime acceptance выполняется отдельно.
