# 005 — Проверить typed journey and quests в Unity

**Исполнитель:** владелец проекта  
**Когда:** после merge consolidated PR #641 в main.  
**Unity:** 6000.6.7f1 / URP.

## Шаги

1. Обновить локальный main до версии, содержащей PR #639.
2. Открыть `2-client/game`, дождаться импорта и проверить Console на compile errors.
3. Выполнить `Tools → Pogranichye → Validate shared v1 fixture`; убедиться, что full journey/quest DTO cases проходят.
4. Войти в поселении и открыть меню просьб:
   - предложения доски и NPC показываются с теми же именами/описаниями, что сервер прислал;
   - активные просьбы показывают прогресс и готовность;
   - accept/turn-in/drop работают только после серверного подтверждения.
5. Начать путешествие по существующей дороге:
   - road overlay показывает destination, progress, ETA и scene из сервера;
   - при событии показывается server text и только присланные options;
   - выбор отправляется как существующий intent; экран не объявляет исход до server frame;
   - в режиме следования за вожаком показывается сообщение «Решает вожак отряда…», кнопки выбора отсутствуют.
6. Проверить переход с дороги в поселение: следующий full frame убирает road overlay, не оставляя локально симулированного ETA/progress.
7. При ошибке приложить Unity Console log и F3 diagnostic dump.

## Что прислать ChatGPT

- Compile и fixture menu: успех/ошибка.
- Quest offers/active menu: отображается корректно?
- Journey overlay/event choice: совпадает с серверным состоянием?
- При ошибке — полный stack trace и diagnostic dump.

## Ограничения

- Не менять server logic, protocol v1 или значения полей.
- Не считать UI-показ доказательством завершения путешествия/квеста.
- Не ставить `!Выполнено` до фактической проверки.
