# 022 — Claude/server: endpoint пространств для многоэтажных зданий

Исполнитель: Claude (Go/server)
Связано: comms/0254, comms/0269, ADR 0004 §10.
Зависимость: согласованная модель global E/N/U и текущий Layout v2.

## Цель
Реализовать серверные descriptors для этажей, подвалов, лестниц, дверных порталов и поверхностей зданий через GET /api/spaces?cx=&cz=. Клиентская ветка ChatGPT уже подготовлена к потреблению этого endpoint.

## Требования
1. Схема envelope и поля — строго comms/0254 и comms/0269. Не считать streaming layer 64 м этажом.
2. Стабильный space ID для здания во всех горизонтальных чанках; стабильные IDs этажей, поверхностей, комнат, порталов и лестниц.
3. Global E/N/U в миллиметрах остаётся канонической позицией; endpoint сериализует метры. Геометрические точки поверхностей/лестниц локальны относительно space.origin.
4. Первая демонстрационная постройка должна быть частью серверной раскладки обычного поселения, а не отдельной клиентской площадкой.
5. Клиентские descriptors не являются разрешением на движение. Авторитетные вход/выход/лестницы/NPC navigation — отдельный этап.
6. me.room.indoor не переиспользовать.
7. Не менять frame v:1; все поля endpoint additive.

## Этапы
- S1: endpoint, DTO/fixture, deterministic chunk membership.
- S2: одна двухэтажная постройка с door portal, floors, surfaces и лестницей.
- S3: Go tests и совместимость старых клиентов.
- S4: отдельный ADR/план для серверной проверки движения по дверям/лестницам и NPC pathfinding.

## Приёмка
- A→B→A возвращает одинаковые descriptors/revision.
- Одинаковый space ID на всех пересекаемых чанках, без дублирования по ID.
- Отрицательные chunk coordinates корректны.
- Лестница соединяет правильные floor IDs и имеет физически непрерывную XYZ polyline.
- Ни одна клиентская локальная геометрия не разрешает пройти через стену/закрытый portal.
- go test ./..., go vet ./..., go build ./... зелёные.
