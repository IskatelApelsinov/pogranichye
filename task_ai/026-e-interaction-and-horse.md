# Task 026 — контекстные действия E и взаимодействие с лошадью

Ответственный клиент: ChatGPT / Unity.
Ответственный серверный контракт: Claude / Go.
Исходная передача: `3-dev/comms/0275-chatgpt-to-claude-interaction-and-horse.md`.

## Цель
Игрок должен смотреть на реальный объект/рабочее место и нажимать E, чтобы начать доступное серверное действие. Лошадь должна быть видна в мире и оседлаться через понятное контекстное взаимодействие.

## Клиентский первый проход
- [x] При серверном interaction descriptor с известным `target_id` использовать уже существующий поддержанный `op:"act"`/goal путь, если он есть в allow-list (например, smithy → forge), а не отправлять generic `op:"interact"` без гарантированного handler.
- [x] Уточнить подписи кнопок «Оседлать» / «Спешиться» в меню персонажа.
- [ ] Проверить все E targets в реальной Unity-сцене, включая raycast/occlusion/target availability.
- [ ] После server WPos лошади добавить world presentation target, E mount/dismount и подтверждённые состояния.
- [ ] Не генерировать положение лошади на клиенте.

## Карта / ориентация
- [x] На north-up карте явно показать север/восток.
- [x] Показать направление взгляда игрока маркером на карте.
- [x] Добавить масштабную линейку.
- [x] Показать до трёх ближайших известных поселений с компасным направлением и расстоянием по прямой.
- [x] Скрывать дорожные связи, если хотя бы один конец не известен персонажу.
- [x] Явно сообщить, что линии графа — связи, а не точная трасса пешего пути.
- [ ] Проверить масштаб/компас/подписи в Unity 6 / URP.

## Ограничения
- Сервер — источник истины для географии, позиции лошади, доступности работ и результата действий.
- Неизвестные поселения/дорожные связи не должны раскрываться на карте.
- Прямое расстояние не выдавать за расстояние по дороге или ETA.
- Не менять frame v:1; только аддитивные данные и обработчики.
