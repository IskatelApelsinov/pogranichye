# 006 — Grok: усиление Go CI (предложение)

**Исполнитель:** Grok (консультант) + владелец / Claude для применения  
**Подсистема:** `.github/workflows/`, `1-server/`  
**Приоритет:** низкий относительно P0 демо, но полезный и дешёвый.

## Цель

Зафиксировать предложение по усилению существующего Go CI и дать готовый YAML, который можно применить одним PR без изменения концепции.

## Контекст

- Текущий workflow: `.github/workflows/go-server-ci.yml` (build + vet + test + 5× E2E).
- Документ с предложением: `3-dev/docs/CI-GO-PIPELINE.md`.
- `go.sum` отсутствует — кэш по нему убран из предложения.
- Smoke `-demo -days 30` добавлен как лёгкая проверка «мир крутится».

## Шаги

1. Прочитать `3-dev/docs/CI-GO-PIPELINE.md`.
2. (Владелец / Claude) При желании заменить содержимое `go-server-ci.yml` на предложенный YAML.
3. Убедиться, что CI зелёный на `main` после замены.
4. Не трогать Unity, протокол и ADR.

## Ограничения

- Не менять существующие файлы без явного решения владельца (Grok пушит только новые).
- Не добавлять внешние зависимости ради CI.
- Race только на ключевых пакетах ядра, чтобы не раздувать время.

## Критерии готовности

- Документ `CI-GO-PIPELINE.md` в репозитории.
- Задача создана.
- Владелец решил: применять сейчас / отложить / изменить.
