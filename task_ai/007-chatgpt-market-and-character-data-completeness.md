# 007 — ChatGPT: полный показ серверных ресурсов рынка и характеристик персонажа в Unity

**Исполнитель:** ChatGPT  
**Подсистема:** Unity thick client / wire DTO / UI.  
**Связано:** `2-client/game/Assets/_Project/Scripts/Runtime/CoreGameplay.cs`, `2-client/game/Assets/_Project/Scripts/Networking/Protocol/WorldFrame.cs`, `3-dev/docs/CLIENT-WIRE-DTO-COVERAGE.md`, серверные `stateJSON` и `StatsView`.

## Проблема от владельца

В Unity-клиенте на рынке отображается заметно меньше ресурсов, чем реально выдаёт сервер. Аналогично, в меню персонажа отображается меньше характеристик/навыков, чем присутствует в серверном состоянии.

Это не задача «добавить ещё несколько известных названий». Клиент должен показывать полный актуальный набор данных, который реально прислал сервер, включая новые additive v1 поля/ключи, не теряя их из-за жёсткого allow-list или неполного DTO.

## До изменения кода

1. Прочитать `AI_WORK_RULES.md`, протокол v1, актуальные `stateJSON`/серверные view types, `WorldFrame.cs`, парсеры и соответствующие участки `CoreGameplay.cs`.
2. Сверить реальные формы `place.market[]`, `me.stats`, `me.skills` и иных относящихся к характеристикам разделов по Go-коду и fixture. Не предполагать, что «характеристики» = только шесть core stats.
3. Составить coverage: wire path → серверный источник → DTO/parser → UI → причина потери/непоказа. Отдельно проверить ограничение числа строк/пагинацию/scroll, фильтры, пустые/null поля, unknown/additive keys.
4. Проверить, не использует ли UI старую локальную таблицу ресурсов или локальные названия/цены вместо данных кадра.

## Реализация

- Сервер остаётся единственным источником истины; не дополнять и не пересчитывать ресурсы на клиенте.
- Рынок показывает все валидные строки из полного серверного `place.market[]`; если ассортимент длинный — прокрутка/поиск/категории, но без потери строк. Каждая строка использует серверные stock, buy price и sell price, если они присутствуют.
- В меню персонажа показывать все серверные core attributes, skills и иные публичные progression values, которые действительно входят в frame. Не скрывать новые ключи из-за фиксированного списка.
- Для полей с динамическим набором ключей использовать presence-aware typed DTO/extension-data или строго валидируемый адаптер поверх уже проверенного JSON дерева. Не вводить небезопасное повторное чтение сырого wire JSON.
- Сохранить неизвестные additive v1 поля и не превращать отсутствие/null в ноль без прежней документированной семантики.
- Если server payload сам ограничивает ассортимент или не включает часть желаемых данных, не выдумывать их: создать точный handoff Claude с конкретным wire path, примером и обоснованием.

## Первый проход — 2026-11-16

Аудит реального серверного источника завершён:
- `server.stateJSON` отправляет `place.market = sim.MarketView(se,e)` и `me.stats = sim.StatsView(e)`.
- `sim.MarketView` отдаёт все товары с остатком склада и все товары из stash игрока (уникальные позиции, сортировка по ключу), не ограничивает список шестью строками; пиво исключено намеренно и обслуживается интерфейсом корчмы.
- `sim.StatsView` в текущей версии действительно отдаёт шесть core attributes. Остальные уровни развития — отдельный динамический словарь `me.skills`.
- Первопричина клиентского расхождения: UI рынка был ограничен коротким числом видимых строк; лист навыков не показывал все динамические серверные ключи.

Реализация отправлена в PR [#654](https://github.com/IskatelApelsinov/pogranichye/pull/654):
- полный прокручиваемый список `place.market[]`, без клиентского лимита;
- все числовые `me.skills` отображаются динамически, включая новые ключи;
- шесть core attributes остаются отдельным блоком;
- DTO coverage дополнена серверными источниками и семантикой.

Проверки: source review; GitHub Actions run #43766450477 (`Unity-independent C# checks`) на момент записи выполняется. Unity Editor compile и PlayMode не запускались. Сервер и wire v1 не менялись.
