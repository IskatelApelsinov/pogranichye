# Толстый ПК-клиент — проектная проработка

## Главное: сервер уже клиент-агностичен
Сервер говорит намерениями и пушем состояния по WebSocket (JSON). Браузерная
страница — лишь один клиент. Тестовый терминальный клиент (`client_cli.py`) играет
тем же протоколом, не будучи браузером: вход, работа, охота, бой, питьё — всё
round-trip. Значит толстый клиент на ПК — это НОВАЯ ОБОЛОЧКА поверх готового
сервера, логику переписывать не нужно.

## Направление визуала: 2.5D сверху (изометрия)
Договорились целиться в 2.5D — вид сверху под углом, а не плоское 2D и не полное 3D.
Мир — из изометрических «кубиков и ромбиков»: ромб-тайлы земли, кубы-строения,
токены-персонажи. В тонком клиенте уже есть заглушки (SVG в `assets/`, изо-рендер
в сцене) — тот же приём переносится в толстый клиент (в Godot — Node2D/TileMap с
изо-режимом или лёгкий 3D с ортокамерой). Спрайты-заглушки заменяются на арты
по тем же именам файлов.

## Карта мира с туманом войны (зум) — серверная часть готова
У каждого игрока — знание о деревнях (на сервере, поле `known`): 0 — не знает
(🌫 туман), 1 — слышал (🌁 по слухам, виден на карте, можно разведать), 2 — был
лично (всё открыто: население, здоровье, цены). Узнавание РАЗВИВАЕТСЯ: стартом
открыт родной край (свой шард «по слухам», дом — «был»); слухи в таверне проявляют
неведомые деревни; цепочки-доставки раскрывают пункт назначения; прибытие открывает
деревню полностью. Путь возможен только в известные места. В тонком клиенте уже
отрисовано тремя состояниями пилюль.
В толстом клиенте это ложится в **зум до карты мира**: отдалил — видишь регион,
где туман = серое ничто, «по слухам» = тусклый силуэт, «был» = полноценная деревня.
Данные уже в `state.settlements[*].know`.

## Спрайты (план, без скачивания в песочнице)
Сейчас — SVG-заглушки (`assets/`, изометрия) и примитивы в Godot. Для «покрасивее»:
бесплатные CC0-наборы (напр. Kenney.nl isometric/tiny-town) — кладём под теми же
именами файлов, код не трогаем. Лицензии проверяем перед вкладкой; в этой песочнице
сеть ограничена, поэтому ассеты подключим на машине с доступом/в репозитории.

## Что толстый клиент добавляет (чего нет у тонкого)
- **Живой рендер мира** вместо текста: деревня, люди, таверна, дорога — сцена.
- **Интерполяция**: сервер шлёт состояние ~раз в игровой час; клиент плавно
  анимирует между снимками (движение, день/ночь, погода), скрывая дискретность.
- **Бесшовные переходы**: сервер уже греет деревню назначения заранее (LoD), так
  что при «въезде» караваном данные готовы — клиент показывает дорогу и въезд без
  загрузочного экрана.
- **Мини-игры богаче**: вместо DOM — настоящая физика/ввод (прицел, тайминг, кости).
- **Оффлайн-дружелюбие**: толстый клиент держит WS, переживает краткие обрывы,
  переподключается (сессия-cookie/токен сохраняется).

## Стек (канон) и путь
- **Godot 4 + GDScript** (канон): кроссплатформа ПК, встроенный `WebSocketPeer`,
  быстрый прототип сцен. Протокол — наш JSON (`JSON.parse`/`stringify`).
- Этапы:
  1. **Сейчас**: `client_cli.py` — доказательство протокола вне браузера. ✓
  2. **Прототип Godot** — готов в `godot-client/` (Godot 4.3+): гость-вход → cookie →
     WebSocket, пуш и **дельты**, намерения (работа/охота/выпить/сон/в путь/сохранить).
     **Изо-сцена** (`World2D.gd`): ромб-тайлы, кубики-строения, токены-жители; движение
     по времени суток (день — дела, вечер — таверна, ночь — по домам, спят), день/ночь
     затемнением и окнами, зимняя земля. Каркас 2.5D: примитивы → заменить на арты. ✓
  3. **Мир и переходы**: карта деревень, анимация каравана, въезд без загрузки
     (используя заблаговременный прогрев на сервере).
  4. **Мини-игры нативно** + звук/атмосфера таверны.

## Контракт протокола (для реализации клиента)
- Аутентификация по HTTP: `POST /auth/login|register|guest` → cookie `sid`.
- `GET /ws` с этим cookie → апгрейд (RFC 6455). Далее кадры:
  - приходит: `{"type":"state","state":{…}}` (полный снимок для игрока) и
    `{"type":"ack","rid":N,"res":{…}}` (ответ на намерение).
  - отправляется: `{"op":"<имя>","rid":N, …поля}`.
- Намерения (`op`): `state, do{activity,quality}, hunt, strike{quality},
  travel{to}, trade{action,res,amount}, quest{qid}, choose{opt}, deliver{qid},
  house{action}, item{action,id,slot}, craft{id}, build{id}, family, drink, dice{quality},
  fixtavern{quality}, priority{mode}, respawn, save`.
- `state.state` содержит: `me` (персонаж), `settlements` (карта с `hours`/`shard`/
  `current`), `here` (текущая деревня: склад, таверна, квесты, погода, сезон,
  `players_here`), `activities` (с `difficulty`), `trade`, `shop`, `recipes`,
  `plots`, `region` (`shards`,`hot`,`bodies`), и при событии — `encounter`/`choice`.

Любой клиент (браузер, CLI, Godot) реализует только этот контракт — мир один.
