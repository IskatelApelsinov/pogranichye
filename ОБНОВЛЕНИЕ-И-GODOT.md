# Обновление сервера (Docker) и сборка толстого 3D-клиента (Godot)

Эта инструкция — про **обновление уже работающей установки** и **компиляцию
толстого клиента**. Первичная настройка ВМ/сети/Docker — в `INSTALL.md`
(VirtualBox, проброс порта 8090, установка Docker). Здесь предполагается, что
сервер уже разворачивался хотя бы раз.

Термины: **хост** — твой основной ПК; **ВМ** — Debian в VirtualBox; **образ** —
собранная «коробка» с кодом; **пересборка** — заново собрать образ после правок кода.

---

## Часть 1. Обновить и пересобрать сервер в Docker (на ВМ)

### 1.1 Доставить новый код на ВМ
Код правился — на ВМ нужна свежая версия папки проекта. Любой способ:

- **Через Git** (когда подключишь репозиторий):
  ```bash
  cd ~/pogranichye        # папка проекта на ВМ
  git pull
  ```
- **Без Git** — скопировать папку с хоста (общая папка VirtualBox, scp или просто
  заново распаковать архив поверх). Важно, чтобы на ВМ оказались свежие:
  `world/`, `assets/`, `mp.py`, `netserver.py`, `Dockerfile`, `docker-compose.yml`,
  и папки клиентов `godot3d-client/`, `godot-client/` (их в контейнер НЕ кладём —
  они для запуска в Godot на хосте).

### 1.2 Перегенерировать спрайты (если менялись)
Спрайты-заглушки собираются скриптом и лежат в `assets/` (их 27). Если обновлял
`make_sprites.py` — пересоздай:
```bash
cd ~/pogranichye
python3 make_sprites.py          # перезапишет assets/*.svg
```
> Папка `assets/` **копируется в образ** (строка `COPY assets/` в `Dockerfile`).
> Именно отсутствие этой строки раньше давало «не отображаются спрайты».

### 1.3 Пересобрать и перезапустить
```bash
cd ~/pogranichye
docker compose up -d --build
```
- `--build` — заново собрать образ приложения (подхватит новый код и спрайты).
- `-d` — в фоне. База (PostgreSQL) переживает пересборку: её данные в томе `pgdata`.

Полезное:
```bash
docker compose logs -f app       # смотреть логи сервера (Ctrl+C — выйти)
docker compose ps                # статус контейнеров
docker compose down              # остановить (данные БД сохранятся)
docker compose down -v           # остановить И стереть БД (чистый старт)
```

### 1.4 Переменные окружения (по желанию, файл `.env` рядом с compose)
```
DB_PASSWORD=задай_свой_пароль
GAME_ENV=prod        # prod — без гостевого входа; dev — гость включён
GAME_SECURE=0        # 1, если сервер стоит за HTTPS/реверс-прокси
APP_PORT=8090        # внешний порт (должен совпадать с пробросом в VirtualBox)
```
> Для тестов толстого клиента с гостевым входом удобнее `GAME_ENV=dev`
> (тогда вход гостем работает без регистрации). Для «боевого» режима — `prod`.

### 1.5 Проверка после обновления (с хоста, браузер)
Адрес зависит от сети ВМ (см. INSTALL.md): NAT → `http://localhost:8090`,
Bridged → `http://192.168.x.x:8090`.

- [ ] `http://localhost:8090/healthz` → `{"ok": true}`
- [ ] Открывается главная, **видны спрайты** (земля, дома, таверна, деревья, жители)
- [ ] `http://localhost:8090/observe` → таблица сущностей обновляется (раз в 2с),
      видны новые столбцы: черта, здоровье, настрой
- [ ] В таверне работают чат, «Очко», «Дурак»; в «Хозяйстве» — слоты одежды

## Часть 2. Собрать толстый 3D-клиент (Godot) — на хосте

Толстый клиент — отдельная программа на твоём ПК, которая подключается к серверу
на ВМ. Его либо запускают прямо в редакторе Godot (быстро), либо **экспортируют в
исполняемый файл** (.exe для Windows / бинарник для Linux), чтобы запускать без
редактора.

### 2.1 Поставить Godot
1. Скачай **Godot 4.3+** (версия «Standard», GDScript — .NET не нужен) с
   `https://godotengine.org/download`.
2. Godot — это один исполняемый файл, установка не требуется: распакуй и запусти.

### 2.2 Открыть проект
1. Godot → **Import** → укажи папку `godot3d-client/` (где лежит `project.godot`).
2. Открой проект. Это основной 3D-клиент (вид сверху, ортокамера).
   `godot-client/` — старый 2.5D-прототип, можно игнорировать.

### 2.3 Указать адрес сервера
В дереве сцены выдели корневой узел **Main** → в **Inspector** поправь:
- `host` — адрес ВМ с хоста: `127.0.0.1` при NAT-пробросе, либо `192.168.x.x` при Bridged.
- `port` — `8090` (как проброшен).

Запуск в редакторе: **F5**. Сервер должен быть поднят; для гостевого входа — `GAME_ENV=dev`.

### 2.4 Проверка клиента
- [ ] Появляется 3D-деревня (вид сверху), жители-капсулы ходят, день/ночь меняется
- [ ] Клик по жителю — подпись кто это; клик по таверне — подсказка
- [ ] «🎒 Вещи» — панель экипировки (надеть/снять по слотам)
- [ ] «Дрова/Рыба/Травы» — полоска тайминга (пробел/Стоп), результат в лог
- [ ] «Выпить/Очко/Дурак/Спать/В путь» — проходят

### 2.5 Экспорт в исполняемый файл (чтобы запускать без Godot)
1. Первый раз Godot попросит **Export Templates**: меню **Editor → Manage Export
   Templates → Download and Install** (один раз на версию Godot).
2. **Project → Export… → Add…** и выбери платформу:
   - **Windows Desktop** → получится `.exe`.
   - **Linux/X11** → получится бинарник под Linux.
   - (Для другой ОС добавь соответствующий пресет.)
3. Внизу **Export Project…** → укажи папку и имя файла → **Save**.
   - Галочку «Export With Debug» можно снять для «чистой» сборки.
4. Запусти полученный файл — клиент откроется и подключится к серверу
   (адрес/порт зашиты из инспектора; чтобы менять без пересборки — можно позже
   вынести в поле ввода на экране, скажи, добавлю).

> Windows может ругаться на неподписанный .exe (SmartScreen) — это нормально для
> своей сборки: «Подробнее → Выполнить в любом случае».

### 2.6 Частые проблемы
- **Клиент не подключается**: сервер не поднят, или `GAME_ENV=prod` (тогда гость
  отключён — клиент сейчас входит гостем). Для теста поставь `GAME_ENV=dev` и
  пересобери (`docker compose up -d --build`).
- **Неверный адрес**: при NAT используй `127.0.0.1`, при Bridged — адрес из `ip a`.
  Порт должен совпадать с пробросом VirtualBox и `APP_PORT`.
- **Ошибка в Godot при запуске**: пришли текст из нижней панели «Errors» —
  поправлю конкретное место (версии Godot слегка расходятся по API).
- **Export Templates не скачиваются**: проверь интернет/прокси; можно скачать
  `.tpz` вручную и поставить через «Install from File».

## Коротко (шпаргалка обновления)
```bash
# на ВМ
cd ~/pogranichye && git pull           # или скопировать свежий код
python3 make_sprites.py                # если менялись спрайты
docker compose up -d --build           # пересобрать и запустить
docker compose logs -f app             # проверить логи
# на хосте: браузер http://localhost:8090 ; Godot — F5 в godot3d-client/
```
