# Производственный стандарт ассетов Ёфа v1

Статус: рабочий стандарт для новых Unity-ассетов. Все размеры — в метрах Unity (1 unit = 1 m). Для серверных объектов физические размеры, положение и наличие остаются данными сервера; этот документ задаёт только масштаб и качество клиентских моделей.

## 1. Общие правила

- Оси Unity: Y вверх, Z вперёд; масштаб 1:1, без скрытого scale на корне prefab.
- Pivot — у основания по центру для зданий/растительности; у точки хвата для инструмента; у стоп между ступнями для персонажа.
- Реальный рост взрослого человека: ориентир 1.65–1.90 м. Не масштабировать всех NPC под одну «болванку»: пропорции и телосложение — вариативны, рост остаётся правдоподобным.
- Применённые transforms, корректные normals/tangents, единая ориентация, понятные имена, никаких случайных material instances.
- Сначала silhouette и пропорции, затем материалы. Детали не должны ломать читаемость с расстояния.
- Каждый prefab имеет LODGroup, bounds и тестовый вариант на нейтральном освещении. Для мелких объектов допускается один LOD.
- Не создавать коллайдеры на каждой декоративной детали. Простая физическая оболочка отдельно от render mesh.
- Для серверных сущностей клиент не придумывает экземпляры, позиции, жителей, предметы или точки интереса. Он отображает полученные сущности.

## 2. Размеры моделей

| Категория | Рекомендуемые габариты | Комментарий |
|---|---:|---|
| Человек взрослый | высота 1.65–1.90 м | Скелетный root у пола; глаза около 1.55–1.75 м |
| Ребёнок | высота 1.05–1.45 м | Возрастные пропорции, отдельный силуэт |
| Дверь | ширина 0.80–1.05 м, высота 1.85–2.15 м | Проём обязан совпадать с server Layout door DTO |
| Окно жилого дома | ширина 0.45–0.95 м, высота 0.55–1.10 м | Подоконник примерно 0.75–1.15 м |
| Небольшой дом | ширина 5–9 м, глубина 5–11 м, карниз 2.8–4.2 м | Фактические footprint/height — от сервера |
| Большой дом / мастерская | ширина 8–16 м, глубина 7–18 м | Не подгонять server footprint под декоративную модель |

Таблица не переопределяет размеры серверного Layout и не разрешает клиенту менять препятствия. Если серверный footprint и визуальная модель расходятся, сообщить о несоответствии и исправить presentation policy или серверный размер согласованно.

## 3. Геометрия и LOD бюджеты

Ориентиры для одного экземпляра, не абсолютный лимит для всего кадра:

| Категория | LOD0 | LOD1 | LOD2 |
|---|---:|---:|---:|
| Обычный NPC | 25–45k tris | 10–18k | 2–5k |
| Важный персонаж / герой | 45–70k | 18–28k | 4–8k |
| Инструмент в руках | 2–8k | 0.8–2k | billboard/hidden |
| Меч/оружие | 3–10k | 1–3k | 0.3–0.8k |
| Малый дом | 8–20k | 3–7k | 0.8–2k |
| Крупный дом/корчма | 20–45k | 7–16k | 1.5–5k |
| Дерево | 2–8k | 0.8–2.5k | 2 crossed cards / impostor |
| Куст | 0.5–2.5k | 0.2–0.7k | billboard / cluster |

- LOD переходы — плавные, без резкого исчезновения крупных силуэтов.
- HLOD/батчинг для плотной городской застройки; не создавать сотни независимых материалов.
- Прозрачность листвы использовать умеренно; alpha clipping предпочтительнее сортируемого полупрозрачного материала.
- На дальнем плане уменьшать геометрию и частоту деталей, а не размывать всю модель до нечитаемого пятна.

## 4. Текстуры и материалы

| Категория | Основной набор | Размер |
|---|---|---:|
| Герой / уникальный NPC | BaseColor, Normal, Mask/ORM | 2048² |
| Обычный NPC | BaseColor, Normal, Mask/ORM | 1024² |
| Здание крупным планом | tileable PBR + trim/decals | 1024–2048² |
| Дерево / куст | atlas BaseColor + Normal + Mask | 1024–2048² |
| Инструмент / оружие | BaseColor, Normal, Mask/ORM | 512–1024² |
| Мелкий проп | BaseColor + при необходимости Normal | 256–512² |
| Terrain material | tileable PBR | 1024² на семейство |

- Unity URP/Lit; Metallic/Smoothness и AO — в согласованном Mask/ORM packing, описанном рядом с ассетом.
- Texel density согласовать между соседними объектами. Не ставить 4K текстуру на дальний сарай.
- Никакого апскейла низкокачественной карты как замены настоящей детализации. 64–256 px допустимы для мелкого реквизита/дальних LOD, не для фасада вблизи.
- Для каждого набора: исходник, экспорт, лицензия, author/source, цветовое пространство, размер, packing и дата.
- Мипмапы включены; wrap mode соответствует назначению; anisotropic filtering — для дорог/пола/длинных поверхностей.
- Проверять материалы при дневном, сумеречном и тёплом интерьерном свете.

## 5. Архитектура и окна

- Фасад не должен быть глухой коробкой с нарисованными тёмными прямоугольниками. Окно — реальный проём или recessed frame с толщиной откоса, рамой, стеклом/ставнями и внутренним слоем.
- Окна размещать в пределах серверных стен/этажности. Не пересекать несущие стойки и server door.
- Внутренний свет — локальный, тёплый, с ограниченным числом активных point/spot lights; emissive pane помогает читать окно издалека, но не заменяет освещение интерьера.
- Дневной свет должен проникать через окна. Нужны реальные отверстия/правильные normals, световой проём, светлые поверхности и контролируемый ambient; не лечить темноту завышением общего ambient до плоской картинки.
- Ночью включать окна только там, где есть основание: занятый дом, работающий объект, очаг/лампа. Корчма — приоритетная тёплая точка поселения.
- Свет не должен включаться для всех домов одинаково, если серверная занятость/активность известна; если её нет — использовать только осторожный presentation fallback, не утверждая фактическое присутствие NPC.
- URP Additional Lights budget и тени профилировать на целевом слабом GPU. Большинство малых ламп без теней; тени — у ключевых источников.

## 6. Аудио: обязательные группы

| Группа | События / слои |
|---|---|
| Региональная музыка | Отдельные темы для культурных/географических регионов; плавный crossfade при смене региона, без резкого переключения |
| Улица / природа | ветер, листва, птицы днём, насекомые ночью, вода, дождь, снег/метель, далёкие животные |
| Поселение | далёкие голоса, шаги, телега/колёса, собаки, колокол, хозяйственные звуки |
| Корчма | плотный, но тихий crowd murmur, отдельные близкие реплики/смех, посуда, кружки, лавки, очаг, дверь |
| Интерьер | приглушение наружного мира, короткая ранняя реверберация по комнате, шаги по дереву/камню |
| Передвижение | земля, трава, грязь, гравий, камень, доски, снег, вода; шаги должны соответствовать скорости/ритму |
| Бой | выхват оружия, взмах, попадание по ткани/коже/дереву/металлу/щиту, блок, промах, падение; события только по реальному gameplay result |
| Взаимодействие | дверь/засов, сбор, рубка, кузница, рыбалка, крафт |
| Предметы | питьё из кружки, установка кружки на стол, наливание, инвентарные действия — без навязчивого UI beep |
| Голоса | короткие non-verbal chatter/babble слои в толпе, отдельные полноценные реплики для диалогов; не подменять ими смысл общения |

Правила микса:
- Разделить Master / Music / Ambience / SFX / Voices; все громкости сохраняются.
- Музыка не должна непрерывно играть одинаково поверх всех регионов; в безопасных/бытовых зонах — низкая громкость и паузы.
- Амбиент — несколько независимых слоёв, не один бесконечный шум. Внутренние зоны фильтруют/приглушают outdoor layers.
- 3D источники использовать для локальных событий; дальние события объединять в bounded emitter pool.
- Не проигрывать удар/питьё по факту нажатия. Сначала подтверждённое состояние/событие.
- Вокальная толпа должна быть ненавязчивой и не звучать как роботизированный генератор синусоид. Нужны записи с вариациями, рандомизированными интервалами и ограничением повторов.
- Все loops проверять на seamless loop; crossfade при смене биома/интерьера.

## 7. Форматы и импорт

- SFX: WAV 44.1/48 kHz, mono для позиционных, stereo для ambience/music. В Unity — Vorbis compressed для длинных слоёв; PCM/ADPCM для коротких transient по слуховой проверке.
- Музыка/амбиент: WAV master; OGG/Vorbis runtime. Loop markers/точки склейки фиксировать в manifest.
- Mono positional SFX: spatial blend 1, distance curve и max distance по сцене. Музыка/фоновые beds — 2D.
- Не коммитить огромные несжатые masters без необходимости; оригиналы держать в исходном asset pack, runtime exports — в проекте.
- У каждого файла — license record. CC0 подтверждать на странице конкретного файла/пакета, не только по названию сайта.

## 8. Приоритеты внедрения

P0 — исправить окна/дневной интерьер и тёплый ночной свет корчмы; проверить, почему текущие оконные детали не дают ощущения окна.
P1 — заменить процедурные placeholder loops реальными записями; сначала лес/ветер/птицы/ночь/корчма/очаг/шаги/меч/пиво.
P2 — footsteps surface routing и combat SFX, привязанные к фактическим результатам.
P3 — региональные музыкальные темы и биомные/погодные слои.
P4 — модели/материалы по этому стандарту, начиная с корчмы, обычного дома, NPC, инструмента, дерева и кустарника.
P5 — performance pass: voices, draw calls, audio voices, lights, texture memory, LOD.
