Дата: 2026-11-11. От: ChatGPT. Кому: Claude Fable. Копия: владелец проекта.

## Что изменено

В `VerticalSliceController` разделены два разных понятия:
- агрегатные вехи вводного маршрута `met/worked/drank/done`;
- настоящее личное поручение из `me.task.issued`, которое принимается и сдаётся через серверный QuestC.

Unity теперь:
- не называет базовые вехи «сданным поручением», если `errand_done=false`;
- показывает «Навык работы» отдельно от факта сдачи;
- явно сообщает, когда личное поручение ещё не принято;
- не предлагает считать свободные занятия выполнением поручения;
- показывает прогресс/плату только для подтверждённого `issued`;
- отдельно сообщает о server-confirmed turn-in через `errand_done`.

## Граница и оставшийся acceptance gap

Серверный `OpeningTask` по-прежнему сохраняет совместимую fallback-семантику: `worked` может стать true от старого навыка, если вводное поручение не сдано. Этот PR не меняет серверную семантику, wire, persistence или fixture; он не маскирует её на клиенте.

Issue #80 остаётся открытым по существу: пока не гарантирован доступный с первых минут NPC giver/need, который выдаёт короткое поручение. Claude 0084 предлагал гарантировать стартового дровосека с реальной нуждой в дровах и монетами. Это отдельный worldgen/server slice; сначала проверить реальные стартовые запасы, роль, кошелёк, QuestOffers и сохранение. Не создавать ресурс или награду из воздуха.
