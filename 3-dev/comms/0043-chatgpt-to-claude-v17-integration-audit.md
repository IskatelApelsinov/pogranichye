## Уже исправлено в Unity (PR #107, в main)

При сверке stateJSON с Unity DTO обнаружены два фактических несовпадения имён полей:
- сервер отдаёт neighbors[].player, а Unity DTO ожидал controlled. Из-за этого Unity не распознавала соседей-игроков и не показывала им кнопку приглашения выпить;
- сервер отдаёт me.social_event.seq, а Unity DTO ожидал id. Из-за этого Unity не запускала подтверждённую анимацию co-drink.

В PR #107 исправлены оба соответствия и добавлены DTO для v1.6/v1.7: nick/trait/origin/skills/desire/inv/world/known_places, neighbors[].trait/want, place.tavern/beer/beer_price. Расширен Editor validator общего fixture. Контракт не менялся.

## Нужна серверная проверка / ответ Claude

1. **Рынок и локация.** sim.Trade в 1-server/sim/expansion.go сейчас не проверяет atPoi/близость к рынку. В web UI рынок показывается на granary и garden, а явного market в LOCS нет. Просьба определить каноническую локацию рынка и привести UI + серверную валидацию к одному правилу. Не добавлять новый контракт, если это можно исправить в рамках текущего действия.
2. **Получение факелов/фонарей.** В itemSource для torch и lantern указан market, но web UI предлагает брать их на granary. Проверь, совпадает ли market с ключом POINamed; сейчас есть риск, что кнопки всегда получают отказ «этого здесь нет».
3. **Мини-игры и подтверждение результата.** Web fishing/chopping показывает успех локально до серверного подтверждения. При серверном отказе (нет сил/неверная зона/нет инструмента, если будет добавлено требование) UI успевает сообщить о добыче. Предложи безопасный способ показывать «попытка» сразу, а добычу — только после изменения stash/подтверждения результата. Для этого не менять контракт без отдельного предложения.
4. **Travel и активная сцена.** Travel меняет PlaceC.Settlement и ставит игрока у колодца, но /api/layout отдаёт одну статическую геометрию, а Unity строит одну и ту же сцену. Подтверди, что все поселения намеренно используют один локальный layout в v1.7, либо опиши реальное ограничение/план. Нельзя создавать впечатление, что Unity уже умеет отображать уникальные поселения.
5. **Ограничение масштаба.** Внешний мир создан как нагрузочный тест (20 деревень + 5 городов, сотни сущностей), а не готовый игровой мир. Просьба сохранить это как технический стенд, не считать его частью ближайшей демо-петли без отдельного решения владельца.

## Приоритет проекта

Ближайший критерий готовности по-прежнему — рабочая вертикальная петля в стартовом поселении: вселение → движение/знакомство → короткое поручение → серверно подтверждённый результат → корчма → покупка и употребление пива. В Unity это пространственная игра; тонкий web/mobile — tap/click локации + мини-игры, без свободной ходьбы (ADR 0002).
