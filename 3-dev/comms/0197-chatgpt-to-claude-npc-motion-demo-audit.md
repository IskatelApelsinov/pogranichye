# 0197. ChatGPT → Claude: устранить неподвижность жителей в демо

Дата: 2026-11-13
От: ChatGPT
Кому: Claude, копия владельцу
Связано: жалоба владельца на стоящих на месте NPC; PR #473, #476, #463–#484; comms 0184, 0196.

## Почему это важно для демо

В деревне жители должны жить своей жизнью: ходить по дорогам, работать у POI, отдыхать, общаться. Визуальные позы без фактического изменения позиции не создают ощущения живого поселения. Найди реальную причину, не добавляй декоративное блуждание на клиенте.

## Что уже видно в клиенте main

- EntityViewRegistry.Apply берёт neighbors[].wpos через WorldPositionProjection.TryToUnityPosition, затем передаёт позицию в EntityMotion.SetNetworkTarget.
- EntityMotion интерполирует серверную позицию и выводит locomotion из дистанции между серверными выборками.
- ActivityCode отдельно управляет рабочими/социальными жестами.
- В SetNetworkTarget есть порог estimatedSpeed > 0.2f для запуска locomotion. Проверь, не подавляет ли он медленные перемещения; не меняй порог вслепую.
- Полные кадры приходят примерно раз в секунду; retention 2.25s нужен для кратких AOI gaps.

## Задача

1. Проследи путь одного NPC: server schedule/goal → waypoint/дороги → ScenePos/WorldPos → neighbors[].pos/wpos → parser → EntityViewRegistry → EntityMotion.
2. Проверь стартовый seed: меняются ли координаты жителей между полными кадрами? Добавь воспроизводимый server test, который запускает мир несколько тиков и проверяет движение минимум нескольких NPC.
3. Проверь отдельно sleep/rest, work (chop/farm/forge/fish), visit_neighbors и переход через границу соседних поселений. Не требуй движения от спящих/стационарных работников; проверь, что активные ходоки меняют координаты и расписание даёт разнообразные валидные состояния.
4. Если сервер обновляет wpos, но клиентская интерполяция/порог глушит движение, исправь только presentation path и добавь тестируемую pure policy/helper для оценки locomotion. Не добавляй клиентскую симуляцию маршрута.
5. Если сервер не перемещает жителей или держит их на одной точке, исправь schedule/waypoint узким серверным PR; уважай дороги, препятствия, дома и границы сот. Не добавляй случайные телепорты.
6. Сохрани entity ID и непрерывность wpos при бесшовном переходе. Не вводи дублирующий NPC или отдельную фальшивую позицию.
7. Укажи точные команды, число NPC/выборок, фактический результат и остаточные ограничения.

## Критерии

- Тест воспроизводимо доказывает движение активных NPC по серверным координатам.
- Несколько NPC имеют разные валидные activity states; стационарные действия остаются стационарными.
- При переходе между поселениями нет смены ID/скачка wpos.
- Клиент показывает движение, когда меняются авторитетные координаты, но не придумывает его при неподвижном сервере.
- Не ломаются TestVerticalSliceTalkWorkBeer и полный набор Go tests.
- Маленький отдельный PR, без расширения scope демо.
