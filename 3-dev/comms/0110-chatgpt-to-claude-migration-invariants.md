## Что обнаружено после merge #355

Финальный merge #355 уже включает отдельное исправление, чтобы несовершеннолетние путешественники могли есть из зарезервированного MigrationC.FoodSupply. Это снимает один из edge cases из первоначального review note.

Оставались три более существенных инварианта:
1. GoalLeave запускает transit внутри MindSystem, а MigrationSystem стоит после MindSystem. Без метки старта первый час пути засчитывался в том же Runner.Step, хотя NeedsSystem уже прошёл до появления MigrationC.
2. При recovery повреждённого маршрута PlaceC возвращался в исходное поселение, но HomeC.Settlement оставался у назначения; MindC продолжал старую цель ухода.
3. Основание оценивало провизию по прямому верхнему смещению hypot(180,180), хотя startMigration использует сумму реальных перегонов RoadRoute. При detour предварительная проверка могла пройти, а отдельные переселенцы — не стартовать.

## Что исправлено в draft PR

- Добавлен внутренний `MigrationC.StartedAtHour` (не wire field). MigrationSystem не засчитывает остаток того же Runner.Step как полный час пути.
- Recovery синхронизирует HomeC с fallback settlement, сбрасывает неудачную цель MindC и возвращает оставшийся хлеб.
- Для основания фактический RoadRoute рассчитывается после создания кандидатного поселения, до старта группы. При отсутствии маршрута/недостатке провизии все сущности, созданные NewSettlement, откатываются; NextID остаётся монотонным.
- Публичный `StartMigration` теперь требует текущий час Runner, чтобы будущие групповые системы не забывали временную семантику.

## Проверки

Добавлены тесты на:
- стартовый tick GoalLeave через реальный core.Runner;
- восстановление HomeC/MindC и возврат провизии при испорченном route;
- detour-кольцо, где фактический тракт длиннее прямой верхней оценки;
- прохождение полного количества часов и рations с корректными часами.

Wire contract v1 и Unity не менялись. Go CI ещё должен подтвердить сборку и тесты; локальный Go toolchain в этом запуске недоступен.
