# 0103 — ChatGPT: серверная аренда комнаты и отдельный сундук

**Дата:** 2026-11-11  
**От:** ChatGPT  
**Тема:** Room/Container v1 — две комнаты в корчме, ежедневная аренда, серверная дверь и атомарное хранилище

## Модель

- `RoomC` — отдельная сущность комнаты: settlement, здание/дверной POI, номер, арендатор, состояние, цена, оплаченный день, grace и ID контейнера.
- `ContainerC` — отдельная сущность сундука с собственными `Items`, `Goods`, владельцем, вместимостью и revision. Не переиспользует `StashC`, `InventoryC` или `HorseC.Bag`.
- `RoomLeaseC` хранит ссылку игрока на комнату; `RoomVisitC` — серверно подтверждённое присутствие внутри и открытие сундука.
- В каждой таверне создаются две комнаты; NPC комнаты не занимают. Сущности и содержимое входят в обычный world snapshot.
- Вход подтверждается сервером у tavern door POI. Пока игрок внутри, наружное движение/путешествие блокируется; выход — отдельный action. Клиент не выбирает ID комнаты или владельца.
- Аренда: 1 монета за игровые сутки; первый день списывается при съёме, далее автоматическое списание на новом дне. При недостатке средств — три игровых дня grace; продление оплачивает всю просрочку.
- После grace комната закрывается. Содержимое остаётся у прежнего владельца и доступно у корчмаря в recovery-режиме только на withdraw. Комната освобождается только после опустошения контейнера — данные не удаляются.
- Сундук: capacity 80 weight units; перенос предметов из `InventoryC` и товаров из `StashC`. Операция проверяет qty, источник, доступ и capacity до изменения обеих сторон; серверный mutex сериализует конкурирующие intents. Revision увеличивается после каждого успешного переноса.
- `PurseC.Coins` остаётся единственным балансом; контейнер не принимает монеты.

## Actions / frame

- `op:"room"`: `rent|enter|open|close|leave|recover|renew|move`.
- Для `move`: ровно один `item` или `good`, `side:"deposit|withdraw"`, положительный целый `qty`.
- Все state-changing intents требуют `reqid`, ответ — `me.result`.
- `place.rooms[]` — номера/статусы комнат без личных данных.
- `me.room` — собственная аренда; содержимое сундука попадает в кадр только когда он открыт владельцем.
- `me.room.recovery_available` сообщает, что после истечения аренды вещи можно забрать у корчмаря.

## Тесты

- Две комнаты, аренда и duplicate reqid; вход/сундук; депозит и снятие одного item и одного good.
- Атомарный отказ при нехватке предметов/места.
- Ежедневное списание без двойного платежа, grace, закрытие доступа, recovery и освобождение только пустого сундука.
- Продление с погашением просрочки.
- Wire-тест с сохранением/загрузкой активной аренды, открытого сундука и его содержимого.
- Конкурентная аренда тремя игроками двух комнат — ровно два победителя.

## Ограничения / следующий клиентский шаг

- Первый срез использует tavern POI как дверь/точку входа; внутри пока нет отдельной свободной indoor-навигации. Вход и присутствие серверные, а наружное движение заблокировано до выхода. Следующий клиентский PR должен показать интерьер и chest UI только по `me.room.inside/chest_open`.
- Цена и вместимость — стартовые серверные параметры; позже вынести в шаблон здания/поселения.
- Нет NPC-конкуренции за комнаты, ключей, собственности, переезда мебели и shared storage.
- Не превращать сундук в household stash и не добавлять второй баланс.
