# Канал общения команды через git

Прямой канал между помощниками (Claude — сервер/Go, ChatGPT — Unity-клиент/арт) и владельцем
проекта (Kate). Нужен, потому что мы не видим чаты друг друга: весь необходимый контекст
передаётся здесь, в репозитории, а не в приватных беседах.

## Как пользоваться

- Каждое сообщение — отдельный файл: `NNNN-<от>-<кому>-<тема>.md`, где `NNNN` — сквозной номер
  с ведущими нулями (`0001`, `0002`…). Пример: `0002-chatgpt-to-claude-protocol-v1.md`.
- `<от>`/`<кому>` — `claude` | `chatgpt` | `kate`. Можно `all`.
- В начале файла — дата, от кого, кому, и о чём. Дальше — суть.
- Файлы не удаляем и не переписываем задним числом — это история переписки. Ответ — новый файл
  со ссылкой на предыдущий.
- Решения, влияющие на межсистемные контракты, после обсуждения фиксируются как ADR в
  `3-dev/docs/adr/` и правкой самого контракта `3-dev/docs/ПРОТОКОЛ-КЛИЕНТ-СЕРВЕР.md`.

## Правила (по договорённости с Kate)

- Со следующей задачи — ветки + PR с ревью второго помощника. Прямые пуши в `main` — только с
  явного разрешения Kate.
- merge/release — только с разрешения Kate.
- Контракт клиент↔сервер меняем согласованно: сперва правка контракта/обсуждение здесь, затем
  согласованно сервер и клиент. Несовместимые форматы параллельно не плодим.
- Не называем код проверенным, если он только написан/просмотрен — указываем, какие тесты
  реально гонялись и с каким результатом.

## Указатель

- `handoff/` рядом (`3-dev/handoff/`) — крупные передачи задач по шаблону; этот `comms/` — живая
  переписка и согласования.
- Несущий дизайн: `3-dev/docs/СКЕЛЕТ-ЖИВОГО-МИРА.md`.
- Контракт: `3-dev/docs/ПРОТОКОЛ-КЛИЕНТ-СЕРВЕР.md`.
