## Что подтверждено на текущем main

1. **Мир v1.19:** WorldPos, anchor, terrain endpoint, /api/layout?settlement=..., -seamless=on уже есть. StepLands переводит только управляемых игроков. StepNPCMovement остаётся в границах локального Layout.
2. **NPC migration — не бесшовная ходьба:** MigrationC использует ProgressHours, при старте удаляет ScenePosC и ставит PlaceC.Settlement=0. Это сохраняет личность и путь, но NPC исчезает на время абстрактного перехода. Не называть это непрерывным пешим переходом.
3. **Жильё/сундук — только foundation:** RoomC, ContainerC, CreateRoom, MoveContainerGoods/Items, RoomLeaseStateAt, CanAccessRoomChest есть. Но в server.applyIntent нет rent/move runtime действий; в snapshot нет me.room/place.rooms; генерации двух комнат таверны и indoor door entry нет. Визуальный сундук Unity не является доступным хранилищем.
4. **Покупка предметов:** op:take уже платный, с POI/ценой/reqid. Не возвращать бесплатные копии.
5. **Временные квестовые займы предметов:** обязательный follow-up из comms 0131 ещё не реализован. Нужны loan ID, точная связь с активным поручением/выдавшим NPC, учёт loaned quantity и запреты на продажу/передачу/выбрасывание/расходование без явного результата.
6. **Ночной свет:** PR #459 добавляет первый серверный detection modifier по Clock.Hour, InventoryC.Hand и CombatC.Light; это не полноценный LOS/light propagation. Не дублировать этот срез.
7. **Скучивание NPC:** тест #453 / TestStarterVillageResidentsSpreadAndMove подтверждает разные позиции и движение в серверном snapshot. Не менять spawn offsets вслепую; проблема реального билда требует Unity snapshot/transform investigation.

## Приоритет A — комнаты таверны и личный сундук (следующий серверный PR)

Решение владельца уже зафиксировано в comms 0093. Реализовать согласованный первый вертикальный срез, а не ещё один документ:

- Две реальные арендуемые комнаты в стартовой таверне; стабильные Room/Chest entity IDs, сохранение в world save.
- Аренда посуточная по игровому времени; конфигурируемая цена, атомарное списание PurseC.Coins, одна активная аренда на игрока, защита от двух арендаторов на одну комнату.
- Состояния vacant/active/grace/expired вычисляются сервером; истечение аренды не удаляет содержимое.
- Доступ к сундуку проверяется сервером по tenant, settlement, фактической позиции/двери и сроку аренды. Не считать нахождение у стойки автоматическим indoor access.
- op:rent и op:move с обязательным reqid; bounded dedup, me.result, отказ без изменения обеих сторон.
- Переносить только существующие InventoryC.Items и согласованные goods/предметы. Не смешивать StashC, HorseC.Bag, PurseC и новый ContainerC.
- Добавить только подтверждённые поля me.room и place.rooms в полный snapshot; обновить fixture и protocol v1 additive.
- Если indoor POI/дверной переход ещё не поддержан геометрией, сделать явный минимальный door state/entry/exit с серверной проверкой и отдельными тестами; не телепортировать клиентом и не притворяться, что интерьер существует.

Обязательные тесты: конкурирующая аренда; недостаток монет; duplicate rent/move; чужой tenant; неверное поселение/дистанция/дверь; grace/expired; переполнение; отсутствующий товар; rollback; save/load и reconnect; старое сохранение без RoomC/ContainerC.

## Приоритет B — непрерывное глобальное движение NPC

Нужен отдельный дизайн+реализация, не косметический патч StepLands:

- NPC должен сохранять тот же entity ID и физическую мировую позицию при пересечении границы.
- PlaceC.Settlement и локальная ScenePosC могут меняться только как представление текущей области; канонический WorldPos остаётся непрерывным.
- Перемещение по глобальному route/road/terrain должно иметь скорость в реальном времени, а не скачок после MigrationC.ProgressHours.
- Spatial AOI должен показывать сущность клиентам по расстоянию/региону, в том числе на границе двух поселений.
- Не выгружать/пересоздавать сущность при смене settlement; расписание, инвентарь, знакомство, здоровье и отношения сохраняются.
- Старый MigrationC оставить совместимым для старых сохранений и LOD, пока физический маршрут недоступен; не запускать оба механизма одновременно.
- Тесты на переход через границу в обоих направлениях, стабильный ID/WorldPos, save/load посреди пути, два наблюдателя по разные стороны, отсутствие двойного NPC и дублирования населения.

## Приоритет C — loaned quest items

Реализовать обязательный follow-up comms 0131 отдельным PR после аудита всех путей мутации инвентаря. Loaned item можно экипировать/использовать только если действие не уничтожает залоговую единицу; нельзя продать, передать, выбросить или скрафтить. Turn-in/drop/expiry должны отозвать только неиспользованный остаток; если предмет уже уничтожен — явный долг/замена, без бесплатной генерации. Состояние и дедуп сохраняются.
