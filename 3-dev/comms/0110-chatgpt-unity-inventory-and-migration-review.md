## 3. Адресный follow-up по PR #355 — серверная часть

Пожалуйста, возьми отдельный небольшой server-only follow-up с тестами. Не менять wire, Unity,
глобальные координаты или смысл текущего `ScenePosC`.

1. **Первый час миграции.** В `Default()` сейчас порядок
   `NeedsSystem → MindSystem → MigrationSystem`. `MindSystem` может создать `MigrationC`,
   после чего `MigrationSystem` увеличивает `ProgressHours` в том же world hour, хотя
   `NeedsSystem` уже прошёл. В результате стартовый час пути засчитывается без соответствующего
   часа потребностей/пайка. Исправить порядок или явно пропускать первый transit tick. Нужен
   runner-level regression test, где `GoalLeave` запускает миграцию внутри `Default()`, а не
   только тест с заранее созданной `MigrationC`.

2. **Recovery и HomeC.** В некорректном route/endpoint recovery `MigrationSystem` возвращает
   `PlaceC.Settlement` в `m.From`, но не синхронизирует `HomeC.Settlement`. При возврате в
   исходное поселение обновить домашнюю привязку и добавить тест для исчезнувшего destination/
   испорченного route. Содержимое/личность NPC не терять.

3. **Провизия founding-группы.** `foundNewSettlement()` проверяет хлеб через
   `math.Hypot(180, 180)`, но `startMigration()` использует фактический `RoadRoute`.
   Прямая оценка не гарантирует, что реальный путь укладывается в зарезервированные рационы;
   после создания поселения отдельные участники могут не пройти `startMigration`, оставив
   частично собранную группу. До создания поселения рассчитать реальные маршруты и рационы всех
   участников; запуск группы сделать атомарным либо гарантировать все маршруты/запасы заранее.
   Нужен тест, где кратчайшая дорожная цепочка заметно длиннее прямого расстояния и хлеба хватает
   по прямой, но не по фактическому маршруту.

4. **Дети в пути — проверить тестом, не дублировать фикс вслепую.** В diff PR #355 условие детской
   ветки уже содержит `Migration(e) == nil`, а следующая ветка расходует `MigrationC.FoodSupply`.
   Поэтому по текущему коду ребёнок-мигрант, похоже, попадает в travel-ration branch. Добавь
   regression test через `NeedsSystem` для несовершеннолетнего с `MigrationC`, чтобы закрепить
   это поведение; исправлять runtime повторно только если тест выявит реальный дефект.

Критерий: сохранение stable NPC ID, корректный часовой цикл needs/transit, отсутствие частично
основанной группы и корректная HomeC после recovery. Все проверки — на сервере; frame v1 и клиенты
не затрагивать.
