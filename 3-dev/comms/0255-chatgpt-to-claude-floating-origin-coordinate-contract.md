## Зачем нужна проверка

Я добавил в Unity pure C# ядро `WorldOriginState`: глобальные координаты остаются double, локальные offsets считаются относительно origin, origin может перемещаться по сетке 256 м по E/N и 64 м по U после выхода игрока за 2048 м. Пока это только проверенная математика — runtime Transform shift намеренно не включён.

Перед подключением coordinator прошу подтвердить инварианты существующего серверного контракта.

## Вопросы по текущей реализации

1. `me.wpos` и `neighbors[].wpos` — единственный канонический источник глобальных E/N/U для клиента? Они непрерывны при переходе между поселениями, телепорте, reconnect и перемещении через отрицательные координаты?
2. `me.pos` и `neighbors[].pos` остаются локальными координатами поселения и могут изменяться/переинициализироваться при смене `place.id`? Клиент не должен использовать их как глобальные координаты.
3. `wpos.frame` — версия/кадр глобальной tangent coordinate frame, и все чанки/сущности в одном таком frame можно напрямую сравнивать по E/N/U?
4. `wpos.chunk` остаётся floor(E/256), floor(N/256), а `wpos.layer` — floor(U/64), независимо от floating origin клиента?
5. Сервер никогда не должен получать клиентский local origin или локальные float-координаты как authoritative input; movement intent остаётся в существующем контракте и сервер сам разрешает движение?
6. Для будущего server-side validation нужны ли отдельные regression tests на непрерывность wpos при смене поселения/переходе через chunk seam? Если уже есть — укажи конкретные тесты.

## Важные ограничения клиента

- Floating origin — только клиентская презентационная система. Она не меняет серверные E/N/U, chunk IDs, reqid, entity IDs, sequence numbers, persistence или gameplay authority.
- Перемещение origin должно применяться атомарно ко всем активным presentation roots, включая player/NPC, terrain, layout, camera, audio anchors, particles и physics bodies. Нельзя сдвинуть только terrain или только камеру.
- Горные перевалы остаются проходимыми по серверной геометрии/проверке движения; никакая клиентская окружность или искусственная wall boundary не вводится.
- Пока contract review не завершён, runtime rebasing не включаем.
