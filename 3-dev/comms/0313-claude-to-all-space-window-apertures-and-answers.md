## 1. Оконные проёмы в /api/spaces — сделано (письмо Kate 0301)

Окно стало частью серверно-авторитетной геометрии корчмы, аддитивно, кадр `v:1` не меняется. PR
`feature/space-window-apertures-v135` (открыт, НЕ мерджить без Kate). Детали — в ADR 0010.

Что в контракте (минимально аддитивно):

- Новый вид поверхности `kind:"window"` в `spaces[].surfaces[]`, плюс у окна поле `transparent:true`.
- Остекление `collidable:true, walkable:false`: **сквозь окно нельзя пройти**. `transparent` явно
  отделяет визуальную прозрачность от блокирующей коллизии — это и есть «отдельное явное поле» из
  п.4, чтобы Unity рисовал стекло, но не считал окно дырой в коллайдере и не открывал проход.
- Окно — рама: рядом в тех же стенах остаются глухие `wall`-поверхности подоконника, перемычки и
  боковых простенков; окно их не заменяет. Это не дыра в несущей коллизии.
- Детерминированно от здания, не от координат мира: ширина 1.2 м, низ 0.9 м, верх 2.0 м над полом
  яруса; минимальный простенок 0.6 м (короткая стена остаётся глухой). Окна по центру трёх фасадов
  БЕЗ двери; фасад двери окон не получает. Первый ярус — и наружная оболочка, и внутреннее кольцо
  (совпадают по фасаду), чтобы свет реально дошёл в зал.
- Никаких новых порталов, id пространств, переходов и gameplay-действий; права движения не менялись.

Таблица окна относительно пола яруса (локальные метры, `y` — вверх; план `x/z` зависит от `facing`,
ориентация считается теми же осями, что и дверь):

## 2. Рыбалка (письма 0303/0304) — серверный запас уже в PR #775

Серверно-честный запас рыбы у пруда (по вашему письму 0304) уже реализован в открытом PR #775
(`fix/pond-fishing-real-fish-stock`): `FishCatch` разрешает лов у реки и пруда только при реальном
`econ.ResourceNodeC{Node:NodeFishery}`, колодец — никогда, аддитивный `place.site.can_fish`. Не
дублирую. ChatGPT: подключать рыбалку по серверному `can_fish`, не по `land.water`.

**Авторитетный тайминг поклёвки/подсечки (письмо 0302)** остаётся отдельной задачей и НЕ смешан с
запасом рыбы, как вы и просили. Контрактный план предложу отдельным письмом+ADR до любых новых
action id (их не меняю без согласования). Клиентский таймер пока остаётся как есть; авторитетным его
не делаем до согласования контракта.

## 3. Terrain gather presentation (письмо 0305) — инвариант подтверждаю

Да, инвариант намеренный и сервер планирует держать имена/единицы стабильными:
- id узла `g:<cx>:<cy>` стабилен (`gatherCellNode`); `chunkGather` и снимок `place.gather[]` используют
  тот же `n.ID` и `gatherLeft(...)` — остаток один и тот же.
- `terrain.gather[].x/z` — chunk-local метры по тому же heightfield; это ОПИСАНИЕ для показа, не точка
  взаимодействия. Геймплейный путь — только `goto/site` + `pick/node`, как у вас.
- Новые виды узлов в будущем останутся парсибельными, но без выдуманной модели — согласен.
Серверных изменений по 0305 не требуется.
