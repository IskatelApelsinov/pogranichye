## #26 — знание о мире (слухи/квесты). Ответы на твои 6 вопросов

1. **Какие per-character структуры знания уже есть?** Прямого аналога нет, но есть ПРЕЦЕДЕНТ и паттерн:
   `AcquaintC{Known map[ID]bool}` на теле игрока (знакомство с НПС, v1.4). Знание о поселениях сделаю
   так же — отдельный компонент на игроке, в снапшот попадает только известное ЭТОМУ игроку.
2. **Как идентифицируются поселения/регионы/POI/маршруты, что стабильно?**
   - Поселения — сущности с `core.ID` (uint64), у `SettlementC` есть `Name`, мировые координаты `X,Y`
     (версты), `Region ID`. Регионы — свои сущности. ID стабильны в пределах жизни мира.
   - **Важная оговорка (честно):** мир пока НЕ перезагружается из снапшота при старте — он генерируется
     заново, так что ID НЕ переживают рестарт процесса. Для персиста знания нужен сперва wiring
     persistence (отдельная задача). Внутри одной сессии всё стабильно.
   - POI — это `POINamed` в `world_geometry.go` (ЛОКАЛЬНЫЕ координаты сцены одного поселения), версия
     `GeometryVersion`. Маршрутов между поселениями как графа НЕТ.
3. **Минимальная серверная модель фактов + происхождение:**
   `WorldKnowledgeC{ Places map[core.ID]PlaceFact }` на игроке, где
   `PlaceFact{ State uint8 (rumoured|located|visited|known), Source string, Conf uint8, Day int, Facts uint16 (битсет: name|dir|route|danger|service) }`.
   В кадр — только записи этого игрока (undiscovered не светим), поле вроде `me.known_places[]`. Это
   ровно твой инвариант «клиент рисует только выданное».
4. **Идемпотентные апдейты:** один вход `Learn(player, place, state, source, facts)` — МОНОТОННЫЙ
   (только повышает состояние/добавляет факты, не понижает). Тогда повтор того же события — no-op,
   идемпотентность бесплатно. Триггеры: реплика-слух в разговоре, письмо/квест (авторитетное событие),
   физическое прибытие (смена поселения тела → `visited`).
5. **НПС-знание по роли/origin без дорогой симуляции:** считать НА ЛЕТУ в разговоре, не хранить модель
   верований. Источник — роль + домашнее поселение + соседние поселения (по `X,Y`/региону) + последние
   заметные события из уже существующей **летописи** (`ChronicleC`). Рыбак → броды + ближние деревни;
   купец → торговые маршруты (куда реально ходят караваны `CaravanSystem`); стражник → угрозы (война/
   бандиты из летописи). Могут врать/устаревать — просто отдаём факт с `Conf` и `Day`.
6. **Минимальный v1-совместимый путь для демо:** всё знание — серверное, в кадр добавляем аддитивный
   `me.known_places` (кадр остаётся `v:1`). НО: для осмысленного демо «слухи→дорога→другой город»
   нужны ≥2 поселения И перемещение между ними, а межпоселенческого травела в сцене пока нет (в v1.3
   я явно отложил глобальную карту). **Вывод: #26 блокируется травелом по миру.** Предлагаю фазы:
   - Фаза A (можно скоро): знание в пределах ОДНОГО поселения + слухи о СОСЕДНИХ как «rumoured» из
     разговоров/летописи (без травела) — journal с происхождением, карта неполная. Демонстрирует идею.
   - Фаза B (нужен травел): overworld-перемещение между поселениями по `X,Y`, `visited` по прибытию,
     письмо/караван как путь. Это крупная серверная веха — проектируем отдельно.

## #18 — опенинг-миссия (15 минут). Ревью темпа/логики/зависимостей

Дуга и замысел — сильные, поддерживаю (живой мир, личная связь, поражение-как-сюжет, свобода в конце).
Главное — честно развести, **что уже реализуемо на текущих механиках, а что требует новых систем.**

**Реализуемо СЕЙЧАС (шаги 1–4):**
- 1 облёт/посадка — чисто Unity-постановка (клиент).
- 2 растерянность/осмотр — ходьба + коллизии + живая деревня у нас есть.
- 3 первая помощь НПС (кузница/огород/рыбалка) — ровно наши действия: `chop`/`fish`/работа фермера,
  близость к POI. Разные варианты → одно знакомство: ок, вешается на диалог (`talk`/`greet`).
- 4 благодарность + таверна + пиво + новости — у нас есть корчма, `drink`, co-drink, и **новости =
  слухи из летописи** (стык с #26 фаза A). Это самый готовый кусок.

**Требует НОВЫХ систем (шаги 5–9) — честно:**
- 5 нападение на дом, плен жены — нужна авторитетная **машина состояний миссии** (нападение/плен/
  ранение/спасение/письмо). Сейчас такого нет. Бандиты как сущности-люди — тоже нет.
- 6 лагерь за городом, выдача меча — нужен **overworld/место вне деревни** (травел, см. #26 B) и
  предмет-оружие в руках игрока (инвентаря оружия нет).
- 7 бой за пленницу — **бой с ЛЮДЬМИ не реализован.** `battle.Resolve` считает схватку только со
  ЗВЕРЕМ (`beastID`); игрокового ближнего боя, бандитов, числа противников — нет. Магия-разряд (`cast`)
  уже бьёт по зверю, но не по людям. Это отдельная боевая веха.
- 8–9 письмо в соседний город, переход к свободе — упирается в травел + 2-е поселение (#26 B).

**Ответы на твои 6 вопросов к обсуждению (кратко):**
1. Кто НПС и почему к незнакомцу — нарратив, но «значимость за 5 минут» хорошо ложится на наше
   знакомство+совместная кружка (растёт настрой/доверие как состояние).
2. Провал у дома без «отняли управление» — делать поражение авторитетным СОСТОЯНИЕМ мира (не скрытой
   проверкой силы), как ты и пишешь; тогда это честно.
3. Какие первые активности уже настоящие — рубка, рыбалка, работа фермера, выпивка/разговор. Кузница
   как действие игрока — пока нет (НПС-кузнец работает, игрок — нет), но добавить `act:"forge"` просто.
4. Пути в соседний город — РЕАЛЬНО существующих пока нет (нет травела). Не выдумывать — согласен; до
   фазы B опенинг честно заканчивать на «в деревне», без письма-в-другой-город.
5. Минимум состояний для миссии — отдельная машина (`MissionC`/квест-состояние): НПС, семья, пленница,
   бандиты, письмо, стадии. Спроектирую, когда решим делать боевую/травел-вехи.
6. Повторный вход без дублей — идемпотентность по стадии миссии (как `reqid`/монотонные состояния).

**Темп (моё замечание, как в 0035):** сутки мира ≈9.6 c — для 15-мин сессии слишком быстро, время
суток мелькает. Предлагаю демо-профиль с замедленным `tickEach` (×3–4). Логику не трогает.
