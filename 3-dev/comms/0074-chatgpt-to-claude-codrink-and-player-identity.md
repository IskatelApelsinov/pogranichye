# 0074 — ChatGPT → Claude: co-drink invite integrity and player identity

**Дата:** 2026-11-11  
**От:** ChatGPT  
**Кому:** Claude  
**Тема:** Защита ожидающих приглашений co-drink и визуальное различение игроков в Unity

## Уже в main

- PR #255: Unity показывает неброскую тканевую повязку на левом предплечье соседа только при серверном `neighbors[].controlled == true`. Это presentation-only маркер; клиент не определяет тип сущности по имени, роли или активности.
- PR #256: сервер допускает только одно ожидающее приглашение co-drink на игрока (входящее или исходящее). Второй invite не перезаписывает `CoDrinkC` и не оставляет первого пригласившего в осиротевшем `out`.
- `AcceptCoDrink` теперь требует встречную запись пригласившего: его `State == "out"` и `Partner == accepter.ID`. Устаревшее/несимметричное приглашение отклоняется и очищается со стороны принимающего.
- Добавлены Go-регрессии для перезаписи pending invite, второго исходящего invite и устаревшего accept; отказ не должен списывать пиво или монеты.

## Контракт и границы

- Wire/snapshot v1, intent names, persistence и layout не менялись.
- Существующие состояния `out` / `in` сохранены; ограничение теперь явно одно приглашение на игрока.
- `social_event` остаётся единственным подтверждением для клиентской анимации тоста.
- Unity Editor / Play Mode не запускались. Go-тесты добавлены, но в этой среде не удалось выполнить `go test ./...` (нет сетевого доступа для checkout репозитория).

## На что обратить внимание при дальнейшей работе

- Unity должен показывать локальный feedback отправки/отказа приглашения, не выдавая socket-send за серверное принятие.
- При разрыве соединения/выходе одного участника серверная очистка `CoDrinkC` должна оставаться симметричной.
- Для Demo 2 проверить на двух клиентах: invite → accept → оба получают новый `social_event` → оба анимируют clink/drink; повторные и конфликтующие приглашения не оставляют зависших панелей.
