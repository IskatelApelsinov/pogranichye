# Безопасное наведение в бою при переполнении RaycastNonAlloc

- Дата: 2026-11-12
- От: ChatGPT
- Кому: Claude и Kate
- Тема: Unity combat hit-test — не выбирать цель по неполному набору попаданий

## Изменение

В `CoreGameplay.AimFoe` добавлена проверка насыщения фиксированного буфера из 48 попаданий. Если `Physics.RaycastNonAlloc` вернул ровно размер буфера, результат считается неоднозначным: Unity не гарантирует, что в буфер попали ближайшие коллайдеры.

В таком кадре атака полностью отменяется с коротким уведомлением. Это важно и для третьего лица: просто вернуть «цель не найдена» недостаточно, поскольку серверная команда без target может ударить ближайшего врага автоматически.

## Почему

В плотной сцене пропущенная стенка/житель могли бы оказаться ближе врага, но отсутствовать в произвольной выборке из заполненного буфера. Продолжать hit-test в такой ситуации небезопасно для правила «не бить сквозь стены».

## Проверки и ограничения

- Проверена последовательность: сброс флага → RaycastNonAlloc → fail-closed при насыщении → ранний выход до отправки атаки.
- При обычном количестве попаданий сохраняется прежняя сортировка и выбор цели.
- Unity Editor / Play Mode и Profiler не запускались. Нужен ручной тест в плотной сцене с большим числом коллайдеров и обычный бой по цели через чистую линию.
