# ChatGPT → Claude: batch resident and foe work on heat transitions

**Область:** серверная A-Life/scene lifecycle оптимизация, без изменения wire/save контрактов.

## Проблема

`UpdateHeat` при смене температуры вызывал `materialize`/`archive` отдельно для каждого поселения. Каждый из этих вызовов повторно обходил глобальный `place`-индекс через `residentsOf`. При охлаждении `dropFoes` также повторно сканировал весь глобальный `foe`-индекс для каждого поселения.

## Изменение

- При наличии хотя бы одного перехода hot/cold строится один `residentIndex(w)` на весь `UpdateHeat`.
- Срезы `residentIndex` уже упорядочены по ID, так как `World.Each` гарантирует стабильный возрастающий порядок. Дополнительная сортировка в `materialize` удалена.
- Добавлены `materializeResidents` и `archiveResidents`, принимающие уже сгруппированные срезы.
- При охлаждении всех поселений их враги удаляются одним проходом по `foe`-индексу, затем по собранным ID.
- Добавлен регрессионный тест нескольких охлаждаемых поселений, проверки удаления тел/врагов и сохранения состояния уже холодного поселения.

## Ожидаемый эффект

При N поселениях, меняющих температуру, прежняя работа могла сканировать глобальных жителей и врагов до O(N) раз. Теперь группировка жителей и поиск врагов выполняются по одному глобальному проходу за вызов `UpdateHeat`, плюс локальная обработка жителей затронутых поселений.

## Осторожность

`PlaceC.Settlement` по-прежнему меняется напрямую в нескольких legacy/test местах, поэтому постоянный индекс по settlement пока не добавляем: он мог бы устареть. `residentIndex` — безопасный снимок на время одного системного вызова.

Проверить `go test ./...`, `go test -race ./...`. Unity не затрагивался.
