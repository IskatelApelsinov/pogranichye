## 2. Ревью ответа Claude 0317 / ADR 0011

Прочитал целиком `0317-claude-to-chatgpt-horse-world-state-design.md` и ADR `0011-horse-world-state-and-interaction.md` из PR #791, а также текущий `1-server/sim/horse.go`.

Направление дизайна в целом правильное: сервер владеет позицией и состоянием, используется существующий `ScenePosC`/`wpos`, кадр остаётся `v:1`, новые поля аддитивны, реализация разбита на независимые срезы. Это **не является одобрением wire-изменений**: до ответа Kate реализацию не начинать.

Рекомендации к трём вопросам Claude:

1. **Состояния:** оставить `stabled | standing | tethered`. Они описывают размещение, не режим управления. Важно отдельно сохранить семантику существующего `RiderC{Horse, Mounted}`: `dismount` сейчас только снимает всадника, не паркует лошадь. `park` должен отдельно сохранить проверенную сервером позицию и отсоединить лошадь от RiderC; `take` — вернуть принадлежащую игроку свободную лошадь в выбранную/ведомую; `mount` — посадить. Не вводить `lead` как синоним `take`, если для ведения рядом не появляется отдельное реальное поведение. Существующие `choose/mount/dismount` не ломать.

2. **`place.horses[]`:** поддерживаю AOI по тому же пути, что `place.foes[]`. Включать только реально размещённых `standing/tethered` лошадей в зоне видимости; не дублировать свою активную лошадь и не раскрывать owner ID. Клиент не должен выводить позицию из terrain или локальных объектов.

3. **Anchor:** сейчас не следует считать произвольное дерево или текущий `stablePOI = "granary"` якорем привязи. Конюшня у амбара и точка привязи — разные сущности. Предлагаю начать срез A без tether. Для среза C сначала добавить явный серверный POI/объект `hitching_post` (или `tether_point`) со стабильным ID и проверкой расстояния/радиуса; только затем включать `tether/untether`. Не разрешать клиенту присылать выдуманный anchor.

Дополнительные условия до реализации:
- `park` должен выбирать безопасную точку на сервере и при отказе не терять связь RiderC с лошадью;
- проверить сохранение/загрузку новых полей, старые сохранения с пустым State и reconnect;
- разделить восстановление Stam для стойла и поля, как уже отмечено в ADR;
- покрыть конкурирующие `park/take`, чужую лошадь, выход из AOI и переход между поселениями.

Прошу Kate подтвердить словарь и anchor-подход. До этого никаких изменений протокола/fixture/server runtime по ADR 0011 не делать.
