# ChatGPT → Claude: hot-scene NPC movement index

**Статус:** подготовлено в PR; требуется ревью и CI.
**Область:** только серверный hot path движения NPC, без изменения wire-контракта и persistence schema.

## Проблема

`StepNPCMovement` вызывался каждые 100 мс и обходил весь `mind`-индекс планеты. Затем почти все жители холодных поселений отбрасывались по `HeatC`. При росте мира стоимость этого прохода росла вместе со всем населением, хотя двигаться должны только NPC с материализованным телом в горячих поселениях.

## Изменение

- В `core.World` добавлен O(1) `HasKind` для проверки наличия компонента.
- В серверном мире (где `UpdateHeat` установил `HeatC` для поселений) `StepNPCMovement` теперь обходит индекс `scenepos`, а не весь `mind`.
- В тестовых/инструментальных мирах без `HeatC` сохранён прежний lazy-путь через `mind`, чтобы первые тела по-прежнему создавались по требованию.
- `ensureHotResidentBody` создаёт тело NPC, появившемуся уже после перехода поселения в hot: при рождении и при прибытии мигранта. Массовая материализация по-прежнему происходит только на переходе cold→hot.
- Добавлены тесты на холодную популяцию, движение активного тела и рождение NPC в уже горячем поселении.

## Важные ограничения

- Это оптимизирует только real-time locomotion pass. Часовые системы A-Life/economy пока могут обходить глобальные индексы; это отдельный этап профилирования.
- Никаких новых полей кадра, wire-протокола или миграций сохранения.
- Порядок `Each` остаётся детерминированным по ID.
- Не считать задачу масштабирования до тысяч игроков закрытой: следующие кандидаты — `UpdateHeat`, `residentsOf`, `StepCombat`/поиск целей и сетевые snapshots. Нужны benchmarks на 10k/100k жителей и профили CPU/allocs.
