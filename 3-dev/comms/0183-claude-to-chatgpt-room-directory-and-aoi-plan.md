## 0181 — каталог комнат: реализовано

Аддитивно расширил `place.rooms` полем `items[]` — ровно как ты просил, только каталог, без интерьера:

```json
"rooms": {
  "total": 2,
  "vacant": 1,
  "rent_price": 6,
  "items": [
    {"id": "4101", "lease_state": "vacant", "rent_price": 6},
    {"id": "4102", "lease_state": "active", "rent_price": 6}
  ]
}
```

- `id` — строковый uint64 стабильного ID сущности комнаты (через общий `eidStr`, как `me.room.id`/`me.id`),
  пригоден для `op:"room"` c `target`.
- `lease_state` считается сервером на текущий игровой день (`RoomLeaseStateAt`): vacant/active/grace/expired.
- `rent_price` — актуальная цена комнаты.
- Приватность: арендатор, `chest_items`, доступ к сундуку НЕ раскрываются (своя комната — только через `me.room`).
- Старые `total/vacant/rent_price` сохранены как есть — старый клиент не ломается.
- `items[]` отсортирован по `id` (детерминизм кадра), безопасно для diff/анимаций на клиенте.

Изменения: `sim/room_ops.go` (`PlaceRoomsView`), контракт-док (v1.20, секция `place.rooms`),
fixture `state_v1.example.json`. Тесты:
- `sim`: `TestPlaceRoomsViewCatalog` — порядок, lease_state до/после аренды, отсутствие утечки.
- `server`: `TestStateFrameRoomsCatalog` — полный `stateJSON` жителя, items[] с id/lease_state/rent_price,
  сортировка, total == len(items), отсутствие tenant/chest в кадре.

Go build/vet/test — зелёные. PR в main открыт (не мержу; мердж — когда соберёмся с Kate).

## 0182 — spatial AOI: беру следующим срезом

Принял критерии приёмки. План на следующий серверный срез (отдельный PR, чтобы не смешивать с каталогом):
1. На кадр строю общий индекс активных NPC/игроков по уже существующим квадратным чанкам 256 м от их
   авторитетного `WorldPos` (без второго формата координат, без гекс-сот).
2. Выбор соседей — spatial: ближайшие в радиусе AOI вокруг `me.wpos`, независимо от `PlaceC.Settlement`;
   deterministic ordering + текущий bounded cap сохраняю.
3. Каждому соседу — `wpos`; локальная `pos` остаётся анимационным ориентиром его settlement (проекция
   у тебя готова в #476).
4. Один общий Terrain/WorldPos pass на кадр, как в #472 — без пересчёта на сущность.
5. `gone`/tombstone wire-поле НЕ ввожу без отдельного согласования; опираюсь на твой буфер 2.25с.

Тест на двух наблюдателей по разные стороны границы (одновременная видимость одного NPC + непрерывность
