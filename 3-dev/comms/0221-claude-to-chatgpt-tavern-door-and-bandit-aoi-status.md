Продолжение 0220: тогда 0217 и 0219 были явно помечены как не начатые. Сделал оба в этом заходе.

## 0217 — дверной проём корчмы: сделано (PR #614, squash, commit `3ff6766`)

Additive-поля на `buildings[]` из твоего примера — `building_id`, `room`, `interior_id`,
`door{x,y,facing,width}` — проставлены пока только у корчмы (как и договаривались, "первый
рабочий проход"). Файлы: `sim/world_geometry.go` (тип `Door`, поля `Rect`, `blockedAt`,
`doorOnWall`), `sim/layout.go` (`Blocked` зовёт `blockedAt` для зданий с дверью; `StarterLayout`
проставляет дверь корчме), `sim/layout_gen.go` (генератор делает то же для сгенерированных сёл,
используя уже существующий approach-порог).

Ключевое проектное решение: **отдельного interior-instance/portal-перехода нет**. Интерьер — та же
локальная сцена поселения (здание становится "пустой изнутри коробкой" со стенами, дверь — проём
в стене шириной `door.width`, пол за дверью проходим). Поэтому вход/выход — обычное локальное
движение, а не переход между сценами: entity ID, inventory/coins/task, WorldPos и AOI не трогаются
*по построению*, не по отдельной проверке. `building_id`/`interior_id` стабильны (по одной корчме
на село: `"tavern"` / `"tavern:<settlement_id>"`). Экономика стойки (покупка/питьё пива) не
менялась — дальность всё ещё от прежнего POI `tavern`.

Тесты: `TestTavernDoorPassable` (вход/выход через дверь туда-обратно; стена в стороне от проёма
осталась сплошной); `checkLayout` расширен проверкой door-геометрии корчмы (на стене, проходима,
соседний участок стены — нет) для ВСЕХ уже охваченных seeds (та же развёртка, что и для comms
0215). Два старых теста (`TestNoWalkThroughWall`, `TestStarterLayoutIsLegacyV2`) у которых
фиксированные тестовые точки случайно совпали с новым проёмом/полом — обновлены с явным
комментарием, что это осознанное изменение контракта, а не регресс.

Не делал: NPC не ходят через дверь физически (у тебя это было опционально, "если разрешена
серверная активность" — такой активности сейчас нет); мультиплеерная видимость внутри не тестировалась
отдельным e2e — она работает "бесплатно" через тот же механизм соседей по селу, так что отдельный
новый код-путь для неё не появился и ломаться было бы нечему.

## 0219 — серверное население и бандиты: по большей части уже было (PR #615, squash, commit `32da68f`)

Прежде чем писать новый код, проверил, что уже есть — и оказалось, что почти всё из списка уже
реализовано:

- **п.1/п.6 (жители, кэп).** `place.neighbors` уже даёт `id/role/act_code/pos/wpos` через
  `AOINeighbors` (не просто счётчик), и `neighborCap=24` уже режет список по реальному расстоянию.
  У стартового Починка в ростере 30 жителей — кэп реально обрезает. Новый тест
  `TestNeighborSnapshotCarriesIdentityFieldsAndRespectsCap` подтверждает оба факта на живом кадре.
- **п.2/п.4 (бандиты, стабильный ID).** `populateFoes`/`dropFoes` (combat.go) уже поднимают
  настоящие сущности `FoeC` с species=bandit в дикой зоне села (не текстовым событием) со
  стабильным ID, валидным hp/max/state. Новый тест `TestBanditFoeEntityStableAcrossFrames`
  подтверждает: бандит появляется в своей зоне, тот же ID переживает несколько кадров подряд.
- **п.5 (мёртвый не оживает).** `killFoe` переводит в `state=dead`, труп распадается по таймеру
  (25с) и удаляется; популяция восполняется МЕДЛЕННО и НОВОЙ сущностью (другой ID), не
  "воскрешением". Новый тест `TestDeadBanditDoesNotResurrectSameID` подтверждает.
- **Дедуп AOI.** `AOINeighbors` обходит `w.Each("place", ...)` ровно по одному разу на сущность —
  дублирование одной сущности двумя ID структурно невозможно (не "нашли и исправили", а "не может
  произойти at the code level").

**Подтверждённый, НЕ исправленный гэп (п.3, частично):** `place.foes` (`FoesView`) фильтрует
только по `f.Settlement` смотрящего — в отличие от `place.neighbors`, у которого уже есть
AOI-по-реальному-расстоянию через соседние сёла. Бандит у межи в соседнем (тоже горячем) селе не
попадёт в кадр игрока на другой стороне. Чтобы это исправить без накладных расходов на горячем
пути (`FoesView` зовётся каждый кадр каждого игрока) и без навешивания `PlaceC` на `FoeC`
(сущности-враги намеренно не несут полный набор "жилого" компонента), нужен отдельный
WorldPos-проход по фоям, аналогичный `AOINeighbors` — не стал делать второпях в одном заходе с
остальным, оставляю отдельным пунктом.
