## Сделано

Новый инструмент `1-server/cmd/pogload` — подключает настоящих WebSocket-игроков к УЖЕ ЗАПУЩЕННОМУ
серверу и прогоняет полный серверный путь, а не держит пустые TCP-сокеты. Каждый бот:

1. `POST /api/register` → `POST /api/login` (уникальный префикс логина `pl-<runID>-<N>-<idx>`),
   **пароли и токены в лог не пишутся**;
2. `GET /ws?token=...&fast=<hz>` — настоящее рукопожатие (сверяю `Sec-WebSocket-Accept`), затем
   читаю и разбираю реальные кадры `v:1`;
3. шлёт только поддерживаемые intents — `op:"goal"` (c `reqid`, проверяю ACK `me.result.reqid/ok`)
   и `op:"move"`; **новых intents и изменений wire contract нет**;
4. считает AOI по `place.neighbors`; open-TCP без валидного первого кадра игроком НЕ считается.

Параллельно — фоновый опрос публичных `GET /api/world|stats|layout|terrain|spaces` (включая
последовательные/дальние/отрицательные чанки) с латентностью и статусами по endpoint.

**Сценарии** (`-scenario`): `co-located` (все на месте — worst-case AOI), `distributed`,
`churn` (уходят/переподключаются — проверяю освобождение сессий, `body.duplicate`, reconnect-время),
`mixed`. **Ступени** `-ramp 1,10,25,50,100` (acceptance target 100). Большой мир — через `-villages`
у pogserver (диагностика 300; 1000 — только профиль).

**Отчёт** JSON + читаемая сводка: попытки/успехи register/login/WS, busy/none резервирования тел,
connect/login/first-frame/ACK/reconnect latency p50/p95/p99, снапшоты (count/bytes/bytes-sec/размер
кадра p50/p95/p99/malformed), HTTP latency по endpoint, AOI max/avg, `/api/stats` сервера на пике,
runtime самого загрузчика, конфиг прогона + commit SHA + Go version + OS/arch + wall-clock.

**Жёсткие функциональные критерии** (поле `passed`): все запрошенные WS-клиенты получили валидный
первый snapshot; нет дублированного управления телом; после закрытия сессии освобождаются
(контрольный бот снова получает тело); HTTP API отвечает во время нагрузки. **Пороги
производительности намеренно НЕ заданы** — как ты и просил, сначала baseline на CI/деве.

Границы соблюдены: только stdlib (свой мини-WS-клиент), **localhost-guard** (для удалённого target
нужен явный `-i-understand-remote`), отдельный `-save` у pogserver, чтобы тестовые аккаунты/мир не
загрязняли пользовательское сохранение. Публичного pprof в production не добавлял — серверные CPU/RSS
снимать внешне.
