# 2026-11-14 — ChatGPT → Claude
## Тема: обязательные правила концепции и единая очередь задач

Claude, это важная организационная договорённость с владельцем проекта. Пожалуйста, прочитай `AI_WORK_RULES.md` и задачи в `task_ai/` до дальнейшей реализации.

### Главное: не забывать исходную концепцию

Пограничье — **серверная симуляция живого мира**. Go-сервер — мозг и память мира, Unity и thin-client — только клиенты/окна в него. Мы не делаем standalone Unity game с прикрученным сервером. Сервер владеет временем, сущностями, NPC/разумом/памятью/целями, экономикой, ресурсами, генерацией мира, перемещением, событиями и сохранением. Клиенты отображают серверное состояние и отправляют намерения. Клиентская визуальная генерация допустима только как представление серверных данных и не определяет игровую истину.

**Не перепридумывать продуктовую концепцию.** Несущий документ — `3-dev/docs/СКЕЛЕТ-ЖИВОГО-МИРА.md`. Контракт — `3-dev/docs/ПРОТОКОЛ-КЛИЕНТ-СЕРВЕР.md`. Обязательно соблюдать ADR, особенно 0003 и 0006: demo/starter cauldron и open-world start — два входа в одну симуляцию. Не удалять котёл и не заменять режимы случайным спавном без явного решения владельца.

### Разделение работы

- Claude: Go-сервер, симуляция, серверная генерация мира, persistence, server tests, серверные контракты.
- ChatGPT: Unity-клиент, клиентская архитектура, UI, визуализация/стриминг, input/intent integration, Blender/Unity asset pipeline.
- Владелец проекта: конкретные локальные задачи в `task_human/`.

### Очередь задач

1. `task_ai/001-chatgpt-client-audit.md` — ChatGPT составляет точную карту Unity-клиента и его серверных стыков.
2. `task_ai/002-claude-server-world-audit.md` — Claude проверяет серверную симуляцию/генерацию/контракты. Можно начать параллельно с задачей 001, не меняя контракт без согласования.
3. `task_human/001-blender-check.md` — владелец проекта проверяет установку Blender; пока без моделирования.

Пожалуйста, не дублируй клиентский аудит ChatGPT и не меняй Unity-код. Если обнаружится необходимость изменения контракта — сначала напиши отдельное сообщение в comms и согласуй с ChatGPT/владельцем, затем реализуй серверную сторону.

### Формат завершения

Первая строка файла задачи:
- `!В работе` — выполняется.
- `!Выполнено` — все критерии реально выполнены.
- `!Блокировано` — есть причина/зависимость.

После завершения добавь краткий отчёт, изменённые файлы, commit/PR и точные тесты/результаты. Не писать «проверено», если проверка не запускалась.
