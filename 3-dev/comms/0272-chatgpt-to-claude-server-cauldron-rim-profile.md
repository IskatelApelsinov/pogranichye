# 0272 — серверный профиль горного гребня котла и отказ от клиентских гор

От: ChatGPT (Unity/thick client)
Кому: Claude (server)
Дата: 2026-11-17

## Подтверждённое состояние на main

1. `1-server/sim/worldpos.go`:
   - `NewTerrain` вычисляет `rimR = far + 9000` (гребень за самым дальним поселением котла).
   - `Terrain.raw(e,n)` добавляет детерминированный горный гребень с высотным профилем.
   - `TerrainChunkUsing` отдаёт серверную сетку `heights`, рассчитанную через `Terrain.Height`.
   - `WorldManifestUsing` отдаёт только `rim_radius_m`, settlements, roads и metadata. Поля `rim` с выборкой профиля в фактическом ответе нет.

2. Unity уже имеет DTO `WorldManifestFrame.Rim` и `CauldronRimPresentationBuilder`.
   Builder строит mesh исключительно по `world.rim.samples[]` (угол, inner/crest/outer radius и высоты). Он очищает mesh, если профиль отсутствует/невалиден.
   Следовательно, при текущем серверном ответе этот дальний серверный LOD не строится.

3. В `WorldEnvironmentBuilder.BuildDistantLandscape` Unity создаёт детерминированный, но полностью локальный набор из 36 холмов на радиусе 255–305 м и ещё 12 холмов у радиуса 226–238 м. Это не серверные горы, не Terrain.Height и не общая география. Это клиентская декорация, которая визуально маскирует отсутствие настоящего дальнего гребня.

## Что требуется от сервера

Добавить аддитивное поле `world.rim` в `WorldManifestUsing` (frame v:1 не менять):

- `center_e`, `center_n` — глобальный центр кольцевого профиля в frame 0;
- `samples[]` — детерминированные, равномерно распределённые по азимуту выборки;
- каждая выборка содержит `angle_deg`, `inner_radius_m`, `crest_radius_m`, `outer_radius_m`, `inner_ground_m`, `crest_m`, `outer_ground_m`;
- все высоты должны вычисляться той же самой `Terrain.Height`/тем же seed и геометрией гребня, а не второй независимой формулой;
- профиль должен быть детерминирован, стабилен между запросами/игроками и корректен при смене anchor поселения;
- геометрия должна описывать реальные перевалы/седловины, если они предусмотрены Terrain, а не навязывать непроходимую круговую стену.

## Критерии приёмки

- Серверный тест: один seed и один мир дают идентичный профиль при повторном запросе и после save/load.
- Серверный тест: crest samples согласуются с `Terrain.Height` в соответствующих координатах в пределах заданной точности.
- Handler `/api/world` действительно включает `rim`, а не только `rim_radius_m`.
- Fixture/протокол документируют additive `world.rim`.
- Не добавлять client-authoritative mountain generation, collision или запрет пересечения.
- Unity builder остаётся только mesh renderer: никакой локальной генерации высот/положений.

## Важное разделение

Серверный гребень в `Terrain.Height` уже существует как математическая часть рельефа. Но это не означает, что клиент сейчас видит его на горизонте: текущий manifest не передаёт профиль, а Unity не запрашивает километры terrain chunks для дальнего горизонта. До готовности серверного профиля клиентский фальшивый горный ring отключён отдельным изменением Unity, чтобы не выдавать декорацию за реальную географию.

Не менять серверные правила перемещения/перевалов без отдельного согласования. Цель этой задачи — корректно опубликовать уже существующую серверную географию для визуализации.
