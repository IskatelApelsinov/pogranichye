## 6. Нет NPC-разбойников — СЕРВЕР ПОДТВЕРЖДЁН РАБОЧИМ, PR #573

аддитивное серверное изменение, не контракт).

## 9. Нельзя войти в таверну — ПОДТВЕРЖДЁН РЕАЛЬНЫЙ ПРОБЕЛ, нужен контракт (согласен с 0209)
Согласен с диагнозом 0209: `WorldLayoutFrame.IsBlocked` блокирует весь footprint здания, у Layout v2
нет двери/портала/interior id — это не косметика, вход физически невозможен ни с одной стороны.
Существующий `op:"room"` (server.go:826, v1.20) — это ТОЛЬКО аренда комнаты НАД корчмой, не вход на
первый этаж к стойке. Предлагаю конкретный аддитивный контракт для первого шага (только дверь/портал
таверны, не полный интерьерный слой):
- в Layout v2 у здания появляются `building_id` (stable), `door: {x,y,facing,width}`, `room: "tavern"|"house"|...`;
- сервер валидирует проход через `door` (коридор шириной `width`) как единственный проезжий разрыв в
  `IsBlocked` для этого здания; остальной footprint остаётся непроходим;
- внутри — один общий `interior_id` на здание (не per-player instance), стойка/корчмарь существуют как
  сейчас (POI), просто доступны из интерьерных координат, а не только снаружи.
Это `v1.2x`, аддитивно, без изменения существующих полей. Жду подтверждения формата `door`/`room` от
тебя, прежде чем кодить — чтобы Unity и сервер не разошлись по системе координат двери.

## 10. Точки активностей не там — СЕРВЕР подтверждён единым источником, вероятная причина клиентская
`poiByKind`/`targetForGoal` (sim/village_layout.go) и `Anchor`/`WorldPosOf` (sim/worldpos.go) — ОДИН
источник координат для всех POI на сервере; НПС реально идут и останавливаются на этих точках (п.2).
Риск «anchor применён дважды», который называет 0209, описан именно про клиентский
`WorldLayoutPresentationBuilder` (root transform + offset) — на сервере такого дублирования нет.
Прошу сверить конкретно: для tavern/woods/garden/mine/river сравни координату из `place.site`/
серверного POI-вида с тем, что `WorldLayoutPresentationBuilder` ставит в сцену — если не совпадают,
баг в клиентском применении anchor, не в серверных данных.
