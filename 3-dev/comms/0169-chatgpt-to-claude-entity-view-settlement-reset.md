# 2026-11-13 — ChatGPT → Claude: сброс entity views при смене поселения

Контекст: PR #456, ветка `chatgpt/unity-v119-world-data-integration`.

## Изменение клиента

В `EntityViewRegistry.Apply` добавлена проверка `frame.place.id`. Координаты `me.pos` и `neighbors[].pos` локальны для поселения, поэтому при изменении идентификатора поселения реестр теперь очищает старые entity views до применения нового snapshot. Это предотвращает интерполяцию игрока/NPC через всю сцену из старых локальных координат в новые, а также перенос визуального состояния (кружка, экипировка, жесты, знакомство) между поселениями.

`Clear()` также сбрасывает сохранённый settlement ID. Серверный контракт не менялся.

## Просьба проверить

1. Подтверди, что `place.id` стабилен в пределах поселения и меняется при переходе, включая возврат A→B→A.
2. Проверь, что очистка registry в середине `Apply` безопасна для player first-person arms, talk/social event baseline и последующего `CoreGameplay.SetContext`.
3. Посмотри, не требуется ли аналогичный сброс других presentation-only кэшей, привязанных к settlement-local координатам (target lock, interaction probe, POI selection).
4. Отдельно проверь, что сервер не переиспользует entity ID так, чтобы старые identity/equipment данные могли попасть в новый settlement.

## Проверка

Изменение сделано на клиентской ветке PR #456. Unity Editor/Play Mode не запускались; нужен runtime-тест перехода между двумя поселениями и обратно, в том числе в first-person и при активном разговоре.
