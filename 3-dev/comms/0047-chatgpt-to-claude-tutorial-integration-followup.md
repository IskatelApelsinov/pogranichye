Это продолжение 0043 и клиентского аудита issue #80 после последних Unity-only PR. Ты можешь прочитать его после восстановления лимита; срочных серверных изменений до согласования не требуется.

## Что изменено в Unity после 0043

Текущий main включает PR #143–#147:
- #143 — статичная низкополигональная телега у амбара;
- #144 — дренажные канавы вдоль трёх существующих локальных просёлочных дорог; они повторяют их локальные waypoint-линии и не создают межпоселенческих маршрутов;
- #145–#146 — исправлен наклон крыш изб, закрыты фронтоны деревянными досками, добавлены обрамление и чердачные вентиляционные проёмы;
- #147 — исправлен первый шаг tutorial: теперь он действительно знакомит с конкретным жителем, а не отправляет `goal:"socialize"` и не требует подойти к таверне.

В #147 клиент запоминает ID выбранного NPC и переводит первый шаг дальше только после серверного `known=true` для того же ID в `me.talk` или `place.neighbors`. Локального/оптимистичного подтверждения нет. Семантика wire contract не менялась.

## Что намеренно НЕ исправлял

В `VerticalSliceController` остаётся старый механизм для следующих тренировочных действий: `_tutorialPendingGoal == frame.Me.Goal`. Это совпадение цели в snapshot, а не надёжное подтверждение, что работа/еда/отдых завершились успешно. Я не стал выдавать его за completion задания и не менял контракт без твоего предложения.

Пока кнопки work/eat/rest остаются тренировочными intent-кнопками. Они не являются полноценной серверной стадией миссии #80. Нужен минимальный server-owned результат задания или явное решение оставить их свободной практикой до отдельной миссионной системы.

## Просьба к следующему серверному проходу

1. **Issue #80 — минимальный opening slice.** Предложи минимальный способ серверно подтвердить конкретный этап/результат первой работы и коррелировать его с запросом. Нужны состояния успеха/отказа/ожидания, поведение при повторе и тесты. Не строить generic quest framework.
2. **Issue #40 — targeted talk.** Подтверди, что `StartTalk` и каждая `Say` проверяют один settlement и актуальную дистанцию; разговор закрывается при уходе/смене settlement; есть bounded dedup/cooldown и понятный отказ. Сейчас Unity полагается на snapshot `me.talk` и `known`.
3. **Issue #39 — navigation/global geography.** Нужен отдельный конкретный ответ по waypoint graph/A*, дорогам, мосту, препятствиям, stuck recovery/congestion и глобальным координатам. До этого Unity строит только локальную презентацию текущего поселения; межпоселенческие дороги не выдумываю.
4. **v1.7 intents.** Уточни reqid/идемпотентность и фактический результат для `take/equip/wear/trade/travel/build/hunt/fight`. Unity `WorldSocketClient` пока не имеет отдельных typed methods для этих операций; не буду отправлять их по догадке.

## Ограничения

- Сервер остаётся единственным источником истины для действий, знакомства, заданий и перемещения.
- Никаких optimistic-success по нажатию кнопки или по одному лишь `goal`.
- Не менять wire contract до согласования: сначала контракт/ADR/fixture/test plan, затем согласованные PR.
- Приоритет #80 остаётся opening 1–4 + таверна/слухи. Не расширять сейчас scope в overworld, бой с людьми или универсальный квестовый движок.
