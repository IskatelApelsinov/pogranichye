# 0202 — ChatGPT → Claude: activity, interaction and UI audio audit

Дата: 2026-11-13. Основа: main после #532.

Владелец просит проверить не только общий демо-маршрут, но и весь практический слой взаимодействий: активности, интерфейсы, NPC, животных и врагов. Отдельная просьба — сделать звуки интерфейса/нажатий заметно тише.

## 1. Полный аудит активностей
Проверь актуальный Unity-клиент и server handlers для каждой доступной активности: рубка, рыбалка, сбор/огород, кузница, добыча руды, пасека, охота/бой, строительство/ремесло, торговля, питьё/социальные действия, лошадь/животноводство (если доступно).
Для каждой составь матрицу:
- как игрок обнаруживает действие (мир, подсказка, клавиша, окно);
- какие условия нужны (дистанция, POI/feature, инструмент в инвентаре/в руке, ресурс/энергия);
- какой input/intent отправляется;
- где сервер валидирует;
- как UI показывает pending, success и refusal;
- какой результат появляется в authoritative snapshot (inventory/stash/skill/task/result);
- есть ли реальная мини-игра/анимация или пока только кнопка;
- точный тест, покрывающий путь.
Найди тупики: кнопка доступна, но intent невозможен; activity можно вызвать только через меню; клавиша конфликтует; UI обещает результат до серверного подтверждения; игрок не понимает, почему действие недоступно.

## 2. NPC и социальные взаимодействия
Проверь E interaction, targeted talk, знакомство/скрытие имён до знакомства, диалоговые варианты, завершение разговора, приглашения/совместное питьё, торговлю/поручения, server range/visibility checks, reconnect и duplicate reqid.
Проверь, что NPC остаются адресуемыми при смене активности/переходе между поселениями; UI не показывает ложные имена или неактуальные цели.

## 3. Животные
Раздели реальные server entities (лошади/скот/животные мира) и чисто декоративных кур/ambient motion. Не выдавай декоративные объекты за интерактивных.
Проверь: какие животные сейчас существуют в wire snapshot и Unity presentation; можно ли подойти/взаимодействовать/кормить/оседлать/управлять; какие действия действительно поддержаны сервером. Для отсутствующих функций предложи ближайший вертикальный срез без фальшивых кнопок. Особо проверь, не блокируют ли декоративные животные проходы/прицел/POI.

## 4. Враги и бой
Проверь отдельную кнопку lock-on, выбор цели/снятие фиксации, first/third person, блокирование стенами, выбор части тела, атака/защита/уклонение/плетения, stamina/range/LOS, серверное подтверждение попадания/урона/смерти/добычи. Проверь, что E interaction и combat input не конфликтуют, а NPC/животное не выбирается как foe. Сверь подсказки с реальными bindings.

## 5. Интерфейс и звуки
В текущем WorldAudioDirector есть world/action SFX, но по предварительному осмотру не найден отдельный тихий UI-click sound. Проверь все GUI поверхности (главное меню, HUD tabs, inventory/actions, context prompt, dialogue/chat, minigame, map, settings). Добавь единый короткий ненавязчивый UI click/confirm sound с существенно меньшей громкостью, чем world SFX (ориентир 0.10–0.18 linear gain), без звука на каждый кадр/hover, без двойного срабатывания из двух OnGUI. Отдельно различай click, accepted action и refusal; не проигрывай success sound до server confirmation. Добавь отдельный UI volume setting/слайдер с сохранением в PlayerPrefs, либо документируй, почему текущая настройка SFX уже управляет им. Не меняй громкость шагов/боя/атмосферы ради UI.
Проверь, что UI click не срабатывает на текстовый ввод/drag/slider каждый кадр; максимум один короткий cue на завершённое нажатие.

## 6. Тесты и deliverable
- Сначала audit-only: список подтверждённых проблем с точными файлами/методами и воспроизводимыми шагами.
- Затем один или несколько узких PR: исправлять только доказанные проблемы; не менять wire contract без отдельного предложения.
- Для server поведения — Go tests и точные команды/output.
- Для Unity — добавь/обнови Editor fixtures или статические проверки там, где это уместно; явно отдели их от реального PlayMode.
- В PR приложи таблицу «до/после», тесты и оставшиеся ограничения.
- Не добавляй декоративные интерактивные кнопки без server-backed intent.
- Не делай случайный wandering/локальные награды/локальные животные вместо authoritative simulation.

Приоритет: P0 — действия/интерфейсы, блокирующие прохождение 5–10 минут демо; P1 — взаимодействия NPC/животных/врагов, необходимые для ощущения живого мира; P2 — полировка UI feedback и звука.
