# 0297 — Kate → Claude / ChatGPT: язык мира, имена, внешность и иммерсивный текст

Дата: 2026-11-18. От: Kate. Кому: Claude и ChatGPT.
Связано с PR #745 и атласом 3-dev/content/АТЛАС-МИРА-ЁФ-v1.md.

## Цель

Мир Ёф должен восприниматься как самостоятельный живой мир. В пользовательских текстах не должно быть упоминаний разработки, игры, ИИ, генерации, технических сущностей и внутренних терминов. Это относится к названиям, описаниям, подсказкам, журналу, инвентарю, карте, диалогам, сообщениям о действиях и отказам.

Не делать механическую замену слов. Нужна редактура всего пользовательского текста: естественный русский, единый голос мира, конкретные формулировки, человеческая речь и согласованность с лором. Не менять технические ключи, ID, enum, протокол и логику действий ради косметического текста.

## 1. Мужские и женские имена, фамилии и грамматика

Для каждой культуры завести явные отдельные наборы:
- мужские личные имена;
- женские личные имена;
- при необходимости редкие/неоднозначные формы — отдельным набором, не смешивать с мужским/женским;
- фамильные основы и правила образования фамилий;
- формы обращения, уменьшительные и домашние формы;
- грамматические формы для отображения в предложениях.

Для славянских культур обязательно хранить грамматический род и формы имени/фамилии как данные, а не пытаться склонять произвольную строку эвристикой в Unity:
- именительный: кто? Радобор Градов / Мирослава Градова;
- родительный: кого? Радобора Градова / Мирославы Градовой;
- дательный: кому? Радобору Градову / Мирославе Градовой;
- винительный: кого? Радобора Градова / Мирославу Градову;
- творительный: кем? Радобором Градовым / Мирославой Градовой;
- предложный: о ком? о Радоборе Градове / о Мирославе Градовой.
Учесть неодушевлённость/одушевлённость и исключения; фамилии на -ко, -ых/-их, иностранные и неизменяемые имена не склонять по общему правилу.
Для иных культур — собственные правила: фамилия может быть неизменяемой, порядок имени и фамилии может отличаться. Не русифицировать имена дальних культур автоматически.

У человека должны быть отдельные поля:
- stable person ID;
- sex/gender data required by world model (не выводить из имени);
- culture/origin;
- given name, family name;
- набор грамматических форм;
- preferred short name / familiar address;
- relationship-aware form of address.
Существующие сохранённые имена и ID не менять. Для новых жителей генерация детерминирована seed + culture_id + person_id. Дети получают имена и родовые формы по правилам семьи/культуры.

Проверить весь код имён (включая sim/names.go), сохранения, API DTO, сериализацию и Unity. Нельзя допускать, чтобы NPC по ошибке назывался женским именем с мужским окончанием или наоборот.

## 2. Внешность жителей

Сделать культурно и индивидуально разнообразную систему внешности, не привязанную к одному шаблонному лицу:
- мужские и женские базовые морфологические профили/варианты тела, рост, комплекция и пропорции;
- возрастные группы и возрастные изменения;
- лицо: форма, нос, скулы, подбородок, брови, глаза, кожа, морщины, шрамы, родинки;
- волосы: цвет, длина, фактура, причёски, бороды/усы там, где уместно;
- одежда по климату, достатку, занятию, возрасту, местности и времени года;
- следы труда и быта: мозоли, загар, грязь, заплаты, износ одежды, рабочие инструменты.
Не превращать культурные различия в карикатуру и не делать внешность единственным маркером профессии/происхождения. Разнообразие должно быть детерминированным и не создавать новых server entities на клиенте.

Сначала аудит текущих DTO и доступных моделей/текстур. Если сервер уже передаёт appearance seed/profile — использовать его. Если данных не хватает, предложить компактный аддитивный контракт и fixture; Unity только визуализирует server-owned appearance. Не создавать фиктивных NPC или внешность, меняющуюся при каждом входе/LOD.

## 3. Полная редактура пользовательского текста

Составить инвентаризацию всех видимых строк: Unity C#, ScriptableObjects/assets, локализационные ресурсы, серверные reason/result strings, thin-client, диалоги, туториал, журнал, инвентарь, торговля, корчма, карта, настройки, системные уведомления.

Для каждой строки определить:
- кто говорит (играющий персонаж, NPC, безличная подсказка, технический слой);
- контекст и состояние (успех, отказ, недоступно, ожидание, неизвестно);
- тон и длину;
- placeholders и грамматические параметры;
- ключ локализации, а не текст, зашитый в коде.

Редакторские правила:
- естественные короткие формулировки; никаких «объект успешно активирован», «NPC», «сгенерировано», «в игровом мире», «нажмите для взаимодействия» без контекста;
- вместо общего системного текста — конкретика: «Дверь заперта», «Корчмарь сейчас не у стойки», «Не хватает двух медяков»;
- диалоги должны учитывать знакомство, отношения, статус, профессию, местные привычки, пол/имя собеседника и ситуацию;
- не заставлять каждого NPC говорить одинаковыми шаблонными абзацами; предусмотреть короткие естественные реплики, паузы, приветствия, прощания, перебивания и отказ;
- не выдавать неизвестные игроку сведения; имя/прозвище/описание раскрывать в соответствии с WorldKnowledge/Acquaintance;
- избегать современного игрового жаргона и мета-обращений;
- не менять семантику серверного отказа при литературной редактуре.

Сервер может продолжать возвращать стабильные машинные reason codes. Пользовательский текст строить по локализованному ключу/контексту, а не парсить английскую/русскую прозу. Нужна таблица reason_code → localization_key → placeholders.

## 4. Интерфейс: иммерсивный слой и диагностика

Оставить серверные ответы/диагностику в правом верхнем углу, как просила Kate. Это отдельный компактный технический feed:
- коротко, неброско, ограниченное число сообщений;
- не перекрывает прицел, диалог, карту и важные действия;
- понятная цветовая/иконографическая семантика, без больших окон;
- технические подробности доступны отдельно, если это уже поддерживается.

Обычный интерфейс — максимально иммерсивный:
- минимальный HUD; не держать постоянно на экране панели и подписи, которые не нужны в текущем контексте;
- контекстные подсказки появляются рядом с объектом/внизу и исчезают, когда не нужны;
- состояние персонажа, инвентарь, карта, журнал, настройки открываются осмысленно и не выглядят как отладочная панель;
- избегать постоянных рамок, ярких плашек, избыточных иконок и технических названий;
- текст NPC и имена показывать по мере знакомства; не подписывать весь мир как список объектов;
- проверить разрешения 1280×720, 1920×1080, 2560×1440 и масштабирование UI.
Не убирать важную обратную связь: игрок должен понимать, что действие принято, отклонено или ещё выполняется.

## 5. Локализация — 7 языков

Обязательные языки:
- ru — русский (основной исходный язык и редакторский эталон);
- en — английский;
- zh-Hans — китайский упрощённый;
- ar — арабский;
- fr — французский;
- de — немецкий;
- hi — хинди.

Требования:
- все пользовательские строки имеют стабильные ключи и контекст; никаких захардкоженных фраз в Unity/Go/JS;
- локаль выбирается пользователем и сохраняется; fallback ru/en по явному правилу, отсутствие перевода не должно показывать ключ;
- plural rules и placeholders должны поддерживаться ICU MessageFormat или эквивалентом, не склеивать предложения конкатенацией;
- арабский: RTL layout, bidi, корректный shaping, направление списков/чисел/иконок и тесты смешанного текста;
- китайский: корректные CJK-шрифты и переносы; не использовать латинский fallback;
- хинди: Devanagari shaping, комбинируемые знаки, корректный шрифт;
- немецкий/французский: длинные строки, переносы, расширение кнопок и диакритика;
- проверить шрифтовые лицензии и покрытие символов; шрифт должен быть включён в поставку, если это допустимо лицензией;
- переводы не должны быть машинными буквальными копиями: сначала вычитать ru, затем подготовить качественные переводы с сохранением тона и культурного контекста;
- имена собственные не переводить транслитерацией автоматически: хранить canonical name и локализованную форму/транслитерацию только по правилам культуры и языка;
- технические серверные reason codes стабильны, локализуется только presentation layer.

## 6. Архитектура и границы

Сначала аудит текущего проекта:
1. все Unity текстовые источники и UI;
2. server result/reason strings и контракт;
3. thin-client/web строки;
4. имена/поля пола/внешности/родства и сохранения;
5. текущие шрифты и UI layout.
Вернуть перечень источников строк и план миграции с оценкой охвата.

Не делать один гигантский PR. Разбить:
A. аудит + редакторский гайд + ключи/локализационная инфраструктура;
B. ru cleanup и UX/diagnostic separation;
C. en + fr + de;
D. zh-Hans + ar + hi (RTL/shaping/font QA отдельными тестами);
E. имена/склонения/проверки грамматики;
F. appearance profiles and Unity presentation.

Не менять server frame v1, Layout v2, старые save IDs и семантику действий без ADR/fixture и отдельного согласования. Не блокировать Demo 1/2. Никаких заявлений о runtime/Unity проверке, если Editor не запускался.

## 7. Критерии приёмки

- Нет видимых пользователю строк с упоминанием ИИ, генерации, NPC, клиента/сервера, игры/разработки, если это не техническая диагностика.
- Серверный ответ остаётся в правом верхнем углу, но визуально отделён от обычного игрового текста.
- Русские мужские/женские имена и фамилии корректно склоняются во всех шести падежах, включая исключения и неизменяемые формы.
- В диалогах согласуются имя, пол, обращения и грамматический контекст; тесты на мужские/женские пары и разные культуры.
- Все семь локалей доступны в настройках; нет missing keys, обрезанного текста, tofu-квадратов и сломанного RTL/shaping.
- Смена языка не меняет ID, имена в сохранениях, состояние мира и исходы действий.
- Внешность воспроизводима по стабильному серверному профилю и не меняется при перезаходе/LOD.
- Все источники строк перечислены; есть автоматический тест, ловящий новые захардкоженные пользовательские строки.
- Unity Editor/PlayMode acceptance честно отмечен как pending, если его не запускали.

Приоритет: сначала аудит и архитектура, затем русский текст и разделение UI, затем локали и имена. Appearance — после аудита серверных DTO. Домовой цикл/городские POI и Demo 1/2 продолжаются параллельно и не должны быть заблокированы.
