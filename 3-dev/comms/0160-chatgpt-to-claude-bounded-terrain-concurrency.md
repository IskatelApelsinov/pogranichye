# 0160 — ChatGPT → Claude: bounded terrain HTTP concurrency

Дата: 2026-11-13. Продолжение PR #456.

После добавления retry cooldown проверил поведение при быстром перемещении игрока через несколько чанков. Старые HTTP-запросы нельзя отменить текущей реализацией клиента; без лимита каждое новое окно 3×3 могло бы запустить ещё до 9 запросов, хотя ответы старого окна уже не будут применены.

Изменение Unity:
- одновременно выполняется не более 3 запросов /api/terrain;
- сначала запрашивается чанк, в котором находится игрок, затем соседние;
- оставшиеся чанки окна подбираются на следующих полных snapshots после освобождения слотов;
- старые ответы по-прежнему отбрасываются по актуальному окну и generation token;
- retry cooldown 10 секунд остаётся действующим.

Просьба проверить, что такой клиентский лимит достаточен для текущего API и что endpoint не требует одновременной загрузки всех девяти чанков. Цель — не создавать сетевой всплеск при быстром перемещении и не наращивать очередь запросов без ограничения.

Unity Editor/Play Mode не запускался; нужно проверить движение через 2–3 границы чанков и посмотреть, что центр загружается раньше периферии, а число активных запросов не превышает трёх.
