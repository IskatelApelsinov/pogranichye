# ChatGPT → Claude: вход в дома и интерьерное убранство реальных поселений

Дата: 2026-11-13

## Контекст

Клиентский путь реальных поселений — `WorldLayoutPresentationBuilder.Build(root, layout)` для Layout v2. Сейчас `BuildFootprintBuilding` строит фасадные оболочки из стен/крыши/двери и вывесок. Отдельной interior presentation для этих серверных зданий нет. Богатые интерьерные сцены находятся в старом `ProceduralVillageBuilder`, который относится к tutorial/prototype village и не является интерьерным слоем реальных generated settlements.

Критичный блокер для настоящих интерьеров:
- `WorldLayoutFrame.IsBlocked(x,y)` считает всю площадь `WorldRectFrame` здания заблокированной.
- `WorldLayoutPresentationBuilder.Build` дополнительно создаёт один `BoxCollider` на весь footprint здания.
- Поэтому просто нарисовать мебель за фасадом недостаточно: игрок не может войти в дом, а открытая дверь/видимый интерьер будут обманчивой декорацией.

## Что нужно согласовать/реализовать на серверной стороне

1. **Стабильная идентичность здания и двери.** Добавить в Layout v2 аддитивные поля (не ломая v1/v2 старые клиенты): stable building ID, door/entry position, ширина прохода, направление/ориентация, тип помещения.
2. **Авторитетный вход/выход.** Сервер валидирует интеракцию с дверью и переводит персонажа в interior/room state либо в отдельный interior-space ID. Клиент не должен локально разрешать проход сквозь footprint.
3. **Коллизия проёма.** Серверная проверка движения должна учитывать doorway gap/portal. Не превращать весь дом в проходимую область и не позволять входить через стены.
4. **Общее состояние помещения.** Внутренние интерактивные объекты получают стабильные IDs: сундук/контейнер, кровать/место отдыха, очаг, рабочее место, стол/сиденья. Инвентарь, доступ, занятость и действия остаются серверными.
5. **Мультиплеер.** Несколько игроков должны видеть одного и того же персонажа в одном помещении; вход/выход, трансфер между exterior/interior и reconnect должны сохранять entity ID и состояние. Не делать client-only interior instance.
6. **NPC.** Дверь/комната должны быть доступны серверным маршрутам и активностям NPC, когда соответствующее поведение включено; не телепортировать NPC локально.
7. **Совместимость.** Старые Layout v2 без door/room fields остаются валидны: здания остаются закрытыми/непроходимыми, пока сервер не прислал валидный портал.

## Клиентская часть после контракта

- Строить interior root из server-provided room/building definition и стабильного seed.
- Для дома: пол/потолок, кровать, сундук, стол, лавка, полки, посуда, очаг и небольшие бытовые предметы.
- Для корчмы: стойка, столы, лавки, посуда/кружки, очаг, бочки и полки; интерактивные места должны ссылаться на server IDs, а не только на визуальные объекты.
- Для кузницы: горн, наковальня, верстак, инструменты, уголь/заготовки.
- Статичную мебель и мелочёвку батчить/объединять по материалам, не создавать GameObject на каждый предмет без причины.
- Интерактивные/изменяемые объекты оставлять отдельными view, но использовать pooling и стабильные IDs.
- Учитывать открытые двери, окна, освещение и тени; интерьер должен читаться снаружи через проём, но не выглядеть как плоская витрина.
- Внешние yard props/vegetation не должны занимать дверь, ступени, точки NPC или server POI.

## Приёмка

1. Игрок реально входит в дом через дверь и выходит обратно без загрузочного экрана.
2. Два клиента одновременно входят в одну комнату и видят одну и ту же мебель, игроков и интерактивное состояние.
3. Персонаж не проходит через стены и не входит через закрытую дверь.
4. NPC может использовать дверной проход при разрешённой серверной активности.
5. Старые Layout v2 fixtures без новых полей продолжают проходить validation.
6. Переключение exterior/interior не меняет стабильный entity/building ID и не создаёт дублирующих сущностей.
7. Серверные тесты покрывают doorway collision, вход/выход, concurrent players, reconnect и boundary cases.

## Важное ограничение

Не добавлять фальшивый локальный вход, client-authoritative коллизию или интерьер, который существует только у одного игрока. Если серверный контракт ещё не готов, интерьерные модели можно готовить отдельно, но не подключать их как доступное игровое помещение.
