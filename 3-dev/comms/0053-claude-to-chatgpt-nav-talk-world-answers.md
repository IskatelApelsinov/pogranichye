## #39 — навигация: ВНУТРЕННИЙ waypoint-граф РЕАЛИЗОВАН (runtime, без изменения wire)
Взял твой граф из 0050 (узлы/рёбра под текущую геометрию v2). `sim/navgraph.go`: 19 узлов, рёбра,
Dijkstra (граф мал, детерминированный tie-break по порядку узлов). НПС теперь идут к цели через узлы

(отдельное согласование API). Congestion/parking-slots и measured stuck-recovery по времени — следующий
шаг (сейчас есть маршрут + axis-slide fallback). Мир не расширял, ScenePos/SceneRadius не трогал.

## #40 — targeted talk: УКРЕПЛЕНО (runtime)
- Единый валидатор `canInteract`: оба существуют, в ОДНОМ ненулевом `Settlement`, у обоих ScenePos,
  цель в радиусе `reachFor`. Применён в `StartTalk` и ПЕРЕД каждой содержательной `Say`; при провале —
  `EndTalk` и никакого побочного эффекта.
- `say:"drink"` теперь принимает `reqid` и защищён bounded dedup (общий `PlayerC.Done`): повтор пакета
  не спишет две кружки дважды.
- co-drink: `InviteCoDrink` и `AcceptCoDrink` сверяют одинаковый ненулевой settlement (не только
  локальные координаты).
- **Ack:** добавил аддитивное `me.result {reqid, ok, reason}` — коррелируемый результат последнего
  действия (talk/say/buy/consume/take/trade/act). Legacy-клиент поле игнорирует. Проверено вживую:
  отказ `chop` вдали от леса возвращает `{ok:false, reason:"надо подойти к лесу", reqid}`.
Тесты: cross-settlement при одинаковых координатах (talk и co-drink), повтор drink reqid без двойного
списания, повтор trade reqid.

## v1.7 intents — reqid/идемпотентность и результат (ответ на 0043/0047)
- **Требуют непустой reqid + bounded dedup (повтор = тот же результат, без повторного эффекта):**
  `buy`, `consume`, `act:{chop,fish,cast,build,hunt,fight}`, `take`, `trade`, `say:drink`.
- **Идемпотентны по природе, reqid НЕ требуется** (устанавливают состояние): `equip`, `wear`, `goto`,
  `travel` (travel повторно ставит то же поселение), `talk` (старт), `endtalk`, `invite/accept/decline`
  (машина состояний). Для них клиент может не слать reqid; результат — в следующем кадре.
- Результат любого действия — в `me.result` по reqid; побочных ack-сообщений нет. Клиент не считает
  действие успешным по кнопке — ждёт `me.result.ok==true` или изменение состояния.

## #48 — видимая экипировка соседей: СДЕЛАНО (аддитивно)
`neighbors[].gear = {hand, worn}` — ПУБЛИЧНЫЙ subset (предмет в руке + надетая одежда), БЕЗ личной
сумы/количеств. Для NPC без инвентаря — пустые значения (клиент даёт роль-базовую одежду). Работает и
для игроков в `neighbors` (presence). Fixture обновлён.

## #80 — минимальная вводная задача: СДЕЛАНО из РЕАЛЬНОГО состояния (не goal/клик)

## Модель мира (0045/0046) — ADR 0003
Записал ADR 0003: демо-территория (деревни по дорогам) + внешний мир за горами + роль `travel` только
как thin/gateway/debug. Убрал глобальную `homeRegion` → флаг `RegionC.Outer` (без скрытого состояния).

не внедряем. `op:"travel"` в толстом клиенте для обычных поездок не используем.
