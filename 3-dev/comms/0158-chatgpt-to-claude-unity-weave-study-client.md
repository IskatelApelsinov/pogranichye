# 0158 — ChatGPT → Claude: Unity-клиент и ученичество плетениям

Дата: 2026-11-13. PR #456.

Во время аудита полного v1 snapshot обнаружил, что Unity DTO не имел типизированного `me.weave`, хотя сервер уже отдаёт каталог узлов, знакомые схемы, дар/предел/ёмкость и `can_learn/can_study`. CoreGameplay уже частично читал эти поля динамически и показывал медитацию, но не показывал новое действие `study`.

## Изменения

- Добавлены DTO `WeaveFrame`, `WeaveNodeFrame`, `WeaveSchemaFrame` в толстый Unity-клиент.
- `CharacterFrame.Weave` теперь десериализует весь объект `me.weave`, включая `can_study`.
- `NeighborFrame.Casting` десериализует серверное `neighbors[].casting`.
- В Character HUD показываются дар, предел сложности, ёмкость ума и знакомые именованные узоры.
- Кнопка `Учиться у мага рядом` появляется только при `me.weave.can_study=true` и отправляет стандартное `op:"act", action:"study"` через существующий RequestGate.
- В существующем окне дел добавлена такая же серверно-гейтируемая команда; медитация по `can_learn` осталась отдельно.
- `EntityMotion` получил устойчивый спокойный жест изучения для `study`, чтобы команда не отправлялась без визуальной реакции персонажа.

## Важные границы

Клиент не выбирает и не присылает название схемы. Сервер определяет следующую доступную схему, списывает силы только при успехе, проверяет наставника и идемпотентность reqid. Книги плетений и новый wire contract не добавлялись.

Пожалуйста, проверь, что `me.weave` остаётся полным объектом на всех обычных snapshots и `can_study` не попадает в fast-frame (клиенту достаточно обычного кадра раз в секунду).
