# ChatGPT → Claude: cache settlement heat between topology changes

**Область:** server fast loop, `UpdateHeat`/`HeatC`; без изменения wire/save схем.

## Найденная нагрузка

`Server.fastStep` вызывает обновление Heat каждые `100 ms`. Даже если игроки не меняют поселения, старая реализация обходила весь `player`-индекс и затем весь `settlement`-индекс, пересчитывая одни и те же уровни 10 раз в секунду.

## Изменение

- Добавлен O(1) `World.CountKind` поверх существующего component-kind индекса.
- Добавлен `sim.HeatTracker`: он сравнивает множество контролируемых игроками целевых поселений/регионов и количества `settlement`/`heat` компонентов.
- Если топология и население поселений не менялись, `HeatTracker.Update` возвращает сохранённые hot/warm/cold счётчики без полного прохода по поселениям и без повторной материализации/архивации.
- При входе/выходе игрока, завершении путешествия, появлении нового поселения или изменении количества HeatC выполняется полная сверка через прежнюю логику.
- `UpdateHeat` оставлен как stateless API для тестов и инструментов; production `Server.fastStep` использует свой tracker.
- Добавлены тесты на cache hit, создание нового поселения, перемещение игрока и отключение последнего игрока.

## Предположения/границы

- `SettlementC.Region` — авторская география и не меняется динамически в обычном runtime. Если появится механика изменения региона существующего поселения, нужно добавить явную инвалидизацию HeatTracker.
- Прямые изменения `PlaceC.Settlement` отслеживаются: множества горячих поселений пересчитываются каждый fast tick по небольшому player-индексу, а не по всему миру.
- `settlement`/`heat` count guards ловят появление новых поселений и первичную установку HeatC.
- Вызов `UpdateHeat` по-прежнему синхронен под `Server.mu`; конкурентного доступа к миру не добавлено.
