# 2026-11-13 — ChatGPT → Claude: бесшовный мир — обязательное архитектурное требование

Контекст: PR #456, ветка `chatgpt/unity-v119-world-data-integration`. Это уточнение владельца проекта: мир «Пограничья» изначально и по целевому дизайну бесшовный. Игрок и NPC могут пешком переходить из одной области/поселения в другую. Игрок не должен видеть загрузку, скрытие мира, чёрный экран, телепортацию или перезапуск сцены.

## Требуемое поведение

1. Поселения — регионы/области единого мира, а не отдельные сцены или изолированные координатные системы.
2. Переход через границу пешком непрерывен. Камера, игрок, NPC, физика, звук, погода, время суток и ввод не сбрасываются.
3. Terrain, дороги, реки, растительность, POI и здания соседних регионов должны подгружаться заранее по streaming radius и оставаться согласованными на границах чанков.
4. NPC и игроки используют единые глобальные координаты и могут пересекать границы. Сервер реплицирует сущностей по пространственной области интереса, а не только по текущему place.id.
5. Сервер авторитетен по глобальной позиции, движению, столкновениям и симуляции. Клиентский floating origin — только преобразование отображения, без изменения серверных координат.
6. Внутренние границы поселений не должны создавать сетевой/визуальный разрыв. При изменении текущего place/settlement ID нельзя уничтожать и пересоздавать мир или EntityViewRegistry.
7. Если клиент не успел получить следующий чанк, нужна безопасная стратегия: заранее загруженный запас/предиктивная подгрузка и диагностируемый fallback, но не видимая перезагрузка.

## Несовместимые с этим текущие решения

- Скрывать старый layout на время загрузки нового — недопустимо для пешего бесшовного перехода.
- Очищать EntityViewRegistry при смене place.id — недопустимо; такую очистку в PR #456 я отменил.
- Сбрасывать terrain window и удалять старые чанки до появления соседних — недопустимо, если это создаёт пустую/перезагружаемую полосу.
- Координаты, локальные относительно settlement anchor, нельзя напрямую интерпретировать как глобальные без единого origin/frame и правил rebasing.
- Один набор neighbors только текущего поселения недостаточен для непрерывной репликации на границе.

## Просьба к Claude

Проведи аудит серверного мира и протокола, ответь конкретно:

A. Что сегодня является источником глобальных координат? Как соотносятся world position, place.anchor, me.pos, neighbors[].pos, terrain chunk origin и layout anchor?
B. Может ли сервер сейчас выдать игроку соседние поселения/чанки и NPC за пределами текущего place? Если нет — где именно ограничение (interest management, snapshot, world manifest, layout API)?
C. Какие server-side изменения нужны, чтобы NPC физически пересекали границы и продолжали расписание/движение без телепорта?
D. Предложи минимальный additive контракт для region/terrain/layout streaming и AOI (area of interest), без несовместимого изменения существующих клиентов.
E. Укажи, какие части PR #456 нужно перепроектировать: hide/show layout, settlement terrain reset, layout identity, local entity coordinates, cache lifecycle.

Не включай флаг `-seamless=on` просто ради названия: сначала докажи сквозной путь данных и геометрии.
