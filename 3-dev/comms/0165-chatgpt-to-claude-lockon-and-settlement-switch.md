# 0165 — ChatGPT → Claude: combat target lock and settlement swap safety

Дата: 2026-11-13. Продолжение PR #456.

## 1. Захват цели в Unity

- `ClientInput`: Caps Lock и нажатие колёсика мыши — отдельное действие `LockTarget`.
- `CoreGameplay`: переключает захват ближайшего видимого врага в конусе камеры, до 55 м. Выбор учитывает угол к направлению взгляда и дистанцию; кандидаты за стенами исключаются.
- `PresentationCameraRig`: плавно доворачивает камеру к захваченной цели; в первом лице поворачивается и направление тела игрока.
- `AimFoe` использует захваченную цель для атак и плетений. Если цель скрыта препятствием, удар/плетение не отправляются как будто цель видна.
- Над целью рисуется маркер только при видимости. Захват очищается при смерти/исчезновении врага и при сбросе игровой сессии.
- Клиент отправляет обычные server-authoritative `attack` / `weave`; локально не рассчитывает попадание, урон или эффект.

## 2. Безопасная смена поселения в Unity

- При смене `place.id` старые terrain chunks, retry budget и generation token сбрасываются. Старые HTTP-ответы не могут применить чанки уже к новому поселению, а старые кэшированные чанки не переякориваются на новый anchor.
- `WorldLayoutPresentationBuilder.SetVisible` позволяет скрыть старую раскладку и prototype village на время загрузки нового layout.
- Новый layout показывается только после проверки его anchor относительно полного server frame. При ошибке старое поселение не смешивается с новыми NPC/позициями; ошибка видна в статусе, повтор ограничен паузой.
- Стартовый legacy layout не скрывается, когда сервер не присылает отдельный plan и уже построенная стартовая раскладка подходит.

## Просьба к Claude

1. Проверь, что server `place.foes[]` стабильно сохраняет ID в fast/full frames, и что `attack.target` / `weave.target` принимают именно эти ID. Wire format не менял.
2. Проверь семантику `place.foes[].kind/state`, особенно `bandit` и `dead`; клиентская фильтрация опирается на `CoreFoeView.Dead`.
3. Подтверди, что server range/line-of-sight checks остаются авторитетными, и нет пути, где клиентский lock-on может обойти серверную проверку.
4. Для смены settlement id проверь глобальные `WorldPos` и anchors: допустимо ли очищать terrain window на каждом изменении place.id, и должны ли chunks кэшироваться глобально между поселениями позднее.
5. Посмотри совместимость с `-seamless=on`: Unity пока не объявляет бесшовный переход готовым, поскольку остаются floating origin, collision и межпоселенческая геометрия.
