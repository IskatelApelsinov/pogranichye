## Порядок работ до демо

### P0 — довести основной сценарий 5–10 минут
Сверить актуальный `DEMO-ACCEPTANCE.md` с main и реальными server tests. Для каждого шага явно указать:
- серверный тест/команду и фактический результат;
- клиентский код и конкретный экран/действие;
- что всё ещё требует ручного Unity 6000.6.7f1 прогона;
- где операция может зависнуть/повториться после reconnect или fast/full frame.

Не добавлять новые механики, пока основной маршрут не стабилен: вход → адресный разговор → знакомство → принятие личного поручения → две рубки → сдача тому же жителю → награда → корчма → купить кружку → выпить → запись в летописи.

### P1 — физический интерьер корчмы (ответ на 0185)
Дать конкретный план и небольшой PR, если контракта достаточно:
- реальные серверные anchors/POI входа, внутренней точки и выхода в том же frame;
- enter/exit перемещают серверную WorldPos, сохраняют entity ID и проверяют аренду;
- expired inside: выйти можно, сундук/повторный вход запрещены;
- reconnect/save-load и безопасность от произвольных координат клиента.
Сначала сверить текущий код и контракт; если нужен новый wire field — сначала ADR + fixture + contract review. Не использовать один Indoor bool как подмену физического перехода.

### P1 — два игрока в корчме
Сверить серверные тесты co-drink с текущими Unity DTO/UI:
- два клиента видят друг друга и актуальные позиции;
- приглашение, accept/decline, раздельная оплата;
- синхронное событие тоста/питья;
- reconnect не оставляет призраков и не списывает повторно.
Не объявлять multiplayer beer complete до двух реальных Unity клиентов.

### P2 — аудит клиентских систем
Подготовить короткий перечень end-to-end пробелов для:
- рынок: покупка → подтверждённый результат → предмет в правильном месте (личный инвентарь/закрома);
- инвентарь/экипировка/сумка и визуальное отображение;
- активности у реальных POI (рубка, рыбалка, поле, кузница, пасека);
- NPC: распределённые позиции, движение, act_code → анимация;
- главное меню, кнопки, настройки, звук и качество графики.
Отдельно различать «код/DTO есть», «серверный тест есть», «Unity runtime проверен».
