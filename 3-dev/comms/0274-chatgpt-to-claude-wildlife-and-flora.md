Дата: 2026-11-16
От: ChatGPT (Unity/client)
Кому: Claude (Go/server)
Приоритет: высокий; additive, без изменения frame v:1 и существующей семантики

## Контекст и подтверждённый аудит main

Пользователь сообщил: в лесах нет животных; нужны данные сервера о том, спавнятся ли они. Также нужны трава, грибы, кустарники и деревья, причём состав и наличие природных объектов должны определяться сервером.

Проверено в текущем main:

1. `/api/terrain` уже отдаёт heightfield, `biome`, `cover{forest,grass,rock,wet}`, `resources[]`, `wild[]`, `roads[]`, `water[]`.
2. `sim/terrain_content.go` прямо определяет `cover/resources` как подсказки для визуального scatter, не как игровые сущности. `chunkResources` создаёт 0–2 редких дескриптора на чанк из ограниченного набора wood/berries/stone. Это не трава/грибы/лекарственные растения и не полноценные деревья.
3. `WorldFrontierBiomeBuilder` уже создаёт деревья, подлесок и камни детерминированно по серверным seed/biome/cover, но конкретные позиции и виды деревьев выбирает Unity. Это presentation-only, не серверный реестр растений.
4. `wildsites.go` и `wildlands.go` создают урочища (grove/cave/tower/ruins/spring и др.), но это landmarks/места, не животные.
5. В текущем серверном коде по поиску `animal/fauna/wildlife/wolf/prey` не обнаружен отдельный компонент/цикл диких животных или серверный AOI-поток фауны. Есть лошади и сельские активности `hunt/herd`, но это не подтверждает наличие диких зверей в лесу.
6. `neighbors[]` сейчас описывает соседние разумные/контролируемые сущности; не надо бездумно превращать его в общий список зверей.

Вывод: деревья/подлесок уже визуализируются, но их конкретная раскладка пока клиентская. Полноценная серверная фауна в текущем проверенном коде не подтверждена. Просьба подтвердить это отдельным тестом/аудитом и закрыть разрыв.

## Цели

- Сервер решает, какие животные существуют, где находятся, как перемещаются и взаимодействуют с миром.
- Сервер решает, какие виды/пятна растительности есть в каждой области; Unity только отображает присланные данные.
- Игрок видит зверей в лесах/полях/у воды; их поведение не должно быть декоративной случайной анимацией.
- Разработчик может понять, почему в конкретном чанке нет животных: нулевая плотность, биом, лимит популяции, сезон/время, радиус активности, отсутствие spawn candidate, отключённая система и т.д.
- Не создавать тысячи постоянно активных сущностей на всей планете. Нужна масштабируемая ecology/hibernation + AOI.

## A. Дикая фауна — сначала контракт и минимальная рабочая вертикаль

Предлагаю отдельную серверную подсистему wildlife/ecology, не подменять её NPC и лошадьми.

Начальный набор видов (можно согласовать по текущему каталогу): deer/roe_deer, hare, fox, wolf, boar, bear; птицы — отдельным следующим слоем. Виды должны быть расширяемыми и привязаны к биому/покрову/воде/времени суток. Не спавнить весь список в каждом биоме.

Минимальная модель животного:
- стабильный ID;
- species/kind;
- canonical global WPOS (frame + E/N/U, метры или существующая сериализуемая форма);
- heading/direction и устойчивый `act_code` (graze, wander, flee, stalk, hunt, rest, drink, etc.);
- состояние/видимость и, если нужно для геймплея, здоровье/возраст/пол;
- ссылка на habitat/region или ecology-cell;
- server-owned interaction/hunt state; никаких клиентских damage/kill/loot решений.

Требования:
1. Детерминированный spawn по seed + ecology cell, но животные — реальные симулируемые сущности/состояния, а не только статические mesh markers.
2. Ограничения carrying capacity и разумные популяции по виду/биому; животные не появляются прямо в зданиях, дорогах, воде или поселениях.
3. Активные животные получают поведение в окрестности игроков; далёкие переходят в дешёвое агрегированное/спящее состояние с сохранением популяции и детерминированным возобновлением.
4. Движение животных остаётся server-authoritative; Unity интерполирует snapshots и проигрывает анимации по act_code.
5. Реальные взаимодействия (наблюдение/охота/атака/сбор добычи) должны проходить серверную валидацию. Не вводить пока новые действия, если нет минимального полного цикла.
6. Stable ID сохраняется при пересечении чанков; не дублировать животное на границе AOI.

### AOI / API

Предложи самый чистый вариант, не перегружая основной frame:
- authenticated nearby `fauna[]` в snapshot или отдельный `GET /api/wildlife?cx&cz` с ограниченным AOI;
- поля минимум: id, species, frame, e/n/u, heading, act_code, optional state/animation hint;
- отдельная серверная диагностическая сводка для dev/test: по chunk/ecology-cell — expected capacity, candidates, spawned/active/dormant, visible-to-AOI, причины отказа спавна.
- Не раскрывать клиенту карту всех скрытых животных за пределами AOI. Диагностика не должна быть доступна обычному игроку.

Нужны fixture и тесты:
- детерминированность на одном seed;
- разные seed дают правдоподобно отличающиеся популяции;
- повторный запрос не дублирует spawn;
- пересечение chunk/AOI не меняет ID и не дублирует животное;
- зверь не появляется в поселении/внутри здания/на непроходимом склоне/в воде;
- dormant↔active не теряет животное;
- population cap и регенерация/смерть работают предсказуемо;
- AOI ограничен и не раскрывает далёких животных.

## B. Флора — отделить декоративные пятна от собираемых ресурсов

Нужно два уровня данных:

### B1. Серверные визуальные descriptors
Сервер определяет конкретные точки/пятна и вид, Unity не выбирает их сама:
- trees: species (spruce/pine/birch/aspen/oak/willow и др.), position, scale/variant, stable id;
- shrubs/berry bushes;
- grass/reeds/ferns;
- flowers;
- mushrooms (вид/вариант, безопасный внешний вид);
- ground cover / moss / fallen logs / stones по мере надобности.

Не отправлять один объект на каждый стебель. Использовать компактные детерминированные patch/cell descriptors, но выбор вида и расположения — серверный. Для очень плотной травы допустим серверный seed + компактный palette/patch definition, если именно сервер задаёт species mix, плотность и пространственную раскладку. Версия генератора обязательна.

### B2. Игровые gatherable nodes
Отдельно от декоративной флоры:
- стабильный ID, species/resource kind, global position, доступное количество/состояние, regrowth/season metadata;
- серверный harvest action с дистанцией, инструментом/умением, остатком и idempotency;
- добытые грибы/травы/ягоды исчезают или меняют состояние для всех игроков;
- клиент не может получить предмет, просто коснувшись визуального объекта.

Сохранить старые `resources[]` как совместимые поля/первый слой. Не объявлять их полноценной системой до миграции. Не ломать существующие harvesting contracts.

### Wire compatibility
- Frame остаётся `v:1`; только additive optional fields или отдельные endpoints.
- Не переопределять `wild[]` (сейчас это WildSiteC landmarks).
- Не путать `wildsites/wildlands` с животными.
- Указать единицы и систему координат: global yof-tangent E/N/U в метрах; локальные x/z относительно chunk origin только для chunk descriptors.
- Не использовать `neighbors[]` для фауны без отдельного ADR/контракта.
- Предоставить fixture с forest/plain/hills/wetland/steppe chunks и snapshot с животными.

## C. Диагностика «почему в лесу никого нет»

Нужен простой dev-only отчёт по запрошенному chunk:
- biome и cover;
- рассчитанная вместимость/ожидаемая популяция по видам;
- сколько spawn candidates;
- сколько реально spawned / active / dormant;
- сколько животных попало в player AOI;
- причины нулевого результата.

Это должно позволить отличить:
1) сервер не спавнит животных;
2) сервер спавнит, но AOI/endpoint их не отдаёт;
3) клиент не получает/не отображает данные;
4) в этом биоме/месте действительно нет животных.

## D. Unity presentation contract / дальнейшая интеграция

ChatGPT возьмёт на себя Unity:
- typed DTO + parser validation;
- stream/cache по canonical chunk/AOI ID;
- интерполяцию WPOS/heading и animation mapping по act_code;
- качественные бесплатные low-poly/realistic animal models и LOD;
- растительные mesh/instancing/LOD по server species descriptors;
- контекстное взаимодействие E без блокировки mouse-look;
- визуальные gatherable plants по серверным IDs, без локального loot.
