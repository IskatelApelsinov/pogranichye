# Приёмка демо «Пограничья» — сценарий, проверки, блокеры

Обновлено: 2026-11-10 (Claude Fable 5.2). Один обновляемый документ статуса демо.
Статусы: **PASS** — доказано запуском; **СЕРВЕР** — доказано тестом сервера, клиент не проверен;
**BLOCKED** — проверить нечем; **НЕТ** — не реализовано.

## 1. Запуск

```
cd 1-server
go test ./...                                   # все тесты
go run ./cmd/pogserver -starter -web ../thin-client/web   # сервер на :8090, стартовая деревня
```
Тонкий клиент: открыть `http://localhost:8090/`. Толстый: проект `2-client/game` в Unity 6000.6.7f1,
адрес сервера по умолчанию. Мир после перезапуска сервера создаётся заново (сохранения на диск нет).

## 4. Блокеры демо (по важности)

1. **Unity 6 не проверен вовсе.** Нет редактора в среде исполнителя. Чек-лист — `2-client/game/README.md`.
   Пока он не пройден, демо в толстом клиенте не считается работающим.
2. **Единая очередь Unity.** `buy/consume` и игровые действия из `CoreGameplay` уже идут через
   `RequestGate` (#199). Но `VerticalSliceController` отправлял `talk/say` отдельным путём; PR #205
   перевёл начало разговора и все реплики NPC в тот же gate. Source-level путь теперь единый; реальная
   сборка/PlayMode всё ещё BLOCKED до проверки в Unity 6000.6.7f1.
3. **Летопись отображается в обоих клиентах на уровне исходников** (#208 Unity, #209 thin client); остались Unity Editor/PlayMode и ручной браузерный прогон. Серверная летопись не переживает перезапуск процесса, пока нет disk persistence.
4. **Опьянение** требуется описанием демо, но отсутствует в протоколе: нужно решение владельца.
5. **Сохранение мира** между перезапусками отсутствует.
6. Дорога между деревнями — только абстрактная (`journey`); физических дорог нет.
