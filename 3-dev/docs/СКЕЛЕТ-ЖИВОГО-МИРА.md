# Скелет живого мира — архитектура перезапуска

Это несущий документ после решения переделать проект всерьёз. Коротко: **почему**
старый подход привёл в тупик, **какой** скелет мы строим вместо него, **как** его
расширять, не ломая, и **в каком порядке** двигаться. Писано для команды (Kate +
будущие разработчики), а не «для галочки».

## 0. Решения (зафиксированы с Kate)

- **Движок толстого клиента — Unity (C#).** Под будущий большой открытый мир.
- **Сервер — Go.** Решающий довод: Go здесь реально собирается и тестируется на каждый
  коммит → проверенный код, а не «ИИ вслепую». .NET в окружении не ставится. Клиент
  (Unity/C#) и сервер (Go) общаются по websocket/JSON — общий язык им не нужен, так что
  рассинхрона языков нет. Если позже захотим общие модели на C# — это отдельное решение.
- **Перестройка: новое живое ядро + перенос удачного.** Ядро пишем с нуля (сущности-
  свойства, разум, память без потерь). Переносим из прототипа: систему костей (уже),
  мини-игры, карты, путешествия, социалку — поверх нового ядра.
- **Порядок: сначала живой мир → потом геймплей → потом оптимизация.** (Слова Kate.)

## 1. Почему старый подход умер (разбор лога на 5910 дней)

Лог мёртвого мира показал: все 60 жителей — `idler`, все «сидят в таверне», здоровье у
всех вечные 100, навыки и монеты раздуты до абсурда (cooking 433, 26000 монет), никто не
владеет домом, рода выродились (толпы одинаковых фамилий, мужчины с женскими формами),
дети с огромными навыками. Плюс холодные деревни схлопывались до ЧИСЛА жителей, а архив
лежал в `/tmp` (пропадал при перезапуске).

Корень — **архитектура «системы тикают над плоскими таблицами»**. У такой нет источника
жизни: нет смертности → нет смены поколений → всё застывает в одном аттракторе. Это и
есть «сломанный тамагочи».

**Вывод, легший в основу нового ядра:** живой мир требует (а) сущностей с богатыми
свойствами, которые ничего не теряют; (б) слоя «разума», который сам ставит цели; (в)
настоящего оборота — рождений и смертей; (г) экономики, создающей давление, а не инфляцию.

## 2. Дерево проекта (3 части — как и договорились)

```
1-server/              СЕРВЕР (Go) — мозг и память мира
  core/      (1.1) субстрат: сущности, компоненты-свойства, мир, часы, прокрутка систем
  mind/      (1.4) «мысли» НПС: чистый выбор цели по нуждам и тягам (utility-подход)
  sim/       (1.1) правила жизни: нужды, старение/смертность/рождения, экономика, разум-в-деле
  memory/    (1.2) память без потерь: снимок КАЖДОЙ сущности и свойства + состояние костей
  dice/      (1.3) «наши кости»: детерминированный платформо-стабильный генератор
  worldmut/  (1.5) изменение физического мира (разрушение/постройка, как Red Faction/Rust) — задел
  thin-client/ (1.6) тонкий клиент (мобильная строилка) — ПЕРЕНОС поверх нового ядра
  cmd/pogserver/   точка входа: демо-прогон сейчас, websocket-сервер дальше
2-client/              ТОЛСТЫЙ КЛИЕНТ (Unity)
  game/      (2.1) сам клиент, запуск .exe
  extras/    (2.2) доп. ПО, инструкции, ссылки
  installer/ (2.3) установщик
3-dev/                РАЗРАБОТКА
  docs/      дизайн-документы (этот файл здесь), гайды «как доделывать и добавлять модули»
  tools/     инструменты разработки
  builds/    записи билдов
  archive/   архивы, старый прототип как референс
```

Мапинг на нумерацию Kate (1.1…1.6) — в скобках. Папки названы словами, а не `1.1`, чтобы
Go был счастлив и имена читались.

> Статус переноса: Python-прототип пока лежит в корне репозитория как рабочий референс
> (деплой на нём ещё жив). Его переезд в `3-dev/archive/legacy-prototype/` — ближайший
> отдельный шаг, чтобы не ломать работающий сервер тем же коммитом, что поднимает новый.

## 3. Ядро: сущности и компоненты-свойства (почему так)

Подход — **компонентный** (похож на ECS, Entity-Component-System — «сущность = набор
свойств, системы работают над свойствами»). Но без фанатизма: нам важнее читаемость и
модульность, чем микросекунды.

- **Сущность (Entity)** — вечный уникальный `ID` + мешок компонентов. Житель, предмет,
  дом, деревня — ВСЁ сущность. Id не переиспользуются (умер — его номер больше ничей).
- **Компонент** — одно свойство: `ident` (кто), `vitals` (тело/нужды), `drives` (тяги),
  `mind` (мысли), `skills`, `purse`, `home`, `place`, `settlement`. Это стартовый набор,
  НЕ потолок.
- **Мир (World)** держит сущности и индекс по видам компонентов (чтобы система быстро
  нашла «всех, у кого есть vitals»). Перебор — всегда по возрастанию id (детерминизм).
- **Система** — одно правило (`NeedsSystem`, `MindSystem`, `LifeSystem`). Прокрутка
  (`Runner`) гоняет их по очереди, тик = час мира.

**Как добавить модуль, не трогая ядро (это главная ценность для разработчика):**
1. Объявить структуру-компонент с методом `Kind()` и `core.Register("мойвид", …)` в `init()`.
2. Навесить её на нужные сущности (`world.Spawn(...)` / `world.Attach`).
3. Написать систему, реализующую `core.System`, и добавить в список прокрутки.
Ядро, снимок памяти и другие системы при этом не меняются. Новый вид компонента сам
попадает в сохранение без потерь, потому что память работает через реестр видов.

## 4. Память без потерь (1.2)

Снимок сворачивает КАЖДУЮ сущность и КАЖДЫЙ компонент в JSON `{вид: данные}` плюс
состояние всех потоков костей и часы. Загрузка возвращает мир точь-в-точь и продолжает ту
же последовательность бросков (проверено тестом: снимок → загрузка → побайтное равенство
и одинаковое развитие дальше). Никаких «схлопнуть деревню в число». Масштаб (сотни
деревень) решается позже выгрузкой ХОЛОДНЫХ регионов на диск — но всегда полными
сущностями. Неизвестные виды компонентов при загрузке пропускаются, а не роняют мир
(forward-совместимость для будущих модулей).

## 5. Кости (1.3)

splitmix64 + именованные потоки от мирового семени. Добавил систему — взял свой поток по
имени, чужая случайность не «поехала». Всё воспроизводимо по seed (реплеи, честные игры,
тесты). Портировано с прототипа, алгоритм тот же.

## 6. Разум НПС (1.4) — иерархия потребностей (Маслоу на A-Life)

`mind.Decide` — чистая функция: читает нужды/тяги/ремесло/восприятие мира (Context) и кости,
возвращает ЦЕЛЬ. Решение идёт по ТИРАМ потребностей сверху вниз — закрывается то, что ниже и
острее (нельзя рваться к признанию, пока голоден):

1. **Выживание (сейчас):** голод/усталость/ночь → поесть, поспать.
2. **Безопасность (завтра):** продовольственная тревога деревни (на сколько дней еды на душу),
   кров, доход. ТУТ ключевое: поведение «вырасти хлеб» у пахаря и «заработай» у горожанина
   РОЖДАЕТСЯ из страха будущего голода и ремесла — а НЕ из нашего правила. Кто кормит землёй
   (пахарь/рыбак/охотник) — идёт работать на земле; кто не кормит (кузнец/ткач/повар) —
   обеспечивает доход. Сверхамбициозного кров не держит — уходит за долей.
3. **Принадлежность:** тяга к людям → в таверну.
4. **Признание/рост:** амбиция → мастерство; негде расти — уйти.

Так «береги семена» не записано в коде — оно следствие: когда деревне грозит голод, жители
работают и не транжирят, а в настоящий голод проедают и посевное. Дальше разум усложняется
(планы-цепочки, память, отношения, покупка еды за деньги, квесты «от ума НПС») не трогая ядро.

> Честно: пока переработка (помол у повара, торг) считается агрегатно в `econ`, поэтому
> общинный посевной резерв там ещё держится как упрощение. Следующий шаг — перевести
> производство и владение запасами на уровень самих НПС (личные закрома, купля-продажа),
> чтобы бережливость и купля хлеба были полностью индивидуальными решениями.

## 7. Что уже доказано тестами (v0 ядра)

- Мир ЖИВОЙ за 3000+ дней: оборот поколений (часть исходных умерла, родились новые),
  возраст разбросан (σ≈13), цели разные (НЕ «все в таверне»), деревни растут в города.
- Взросление: ребёнок к 15 годам берёт ремесло → мир не вырождается в сплошных idler'ов.
- Память без потерь и детерминизм переживают сохранение/загрузку.
- Фамилии согласованы по полу (баг «Всеволод Тихонова» устранён на уровне генерации).

## 8. Экономика на законе сохранения (пакет econ) — СДЕЛАНО

Опора на реальное средневековье (сам-3..6 зерна, трёхполье, десятина 10%, нерест, цехи).
Ничего из ниоткуда: добро приходит из КОНЕЧНЫХ угодий и перерабатывается цепочками.
- узлы: пашня / рыбное место / шахта / лес / пастбище — конечный запас + природное
  восстановление (шахта НЕ возобновляется — истощается);
- семенное зерно — отдельный неприкосновенный товар: сев всегда обеспечен;
- сезонный цикл: сев весной, рост летом, жатва осенью; нерест весной (лов закрыт);
- цепочки wheat→bread, ore→tools; порча запасов (тормоз инфляции); десятина держав;
- торговля внутри державы: зерно течёт из избытка в нужду (с потерей на провоз).
Результат (3000 дней, 10 деревень): устойчивый мир с сезонным дыханием (осень сыта, лето —
голодный промежуток), деревни растут в города. Болезнь инфляции склада вылечена.
Осталось на баланс (твоя тема): цены/деньги рынка, межгосударственная торговля, войны за ресурс.

## 9. Сетевой слой и аккаунты — СДЕЛАНО (сервер ЗАПУСКАЕТСЯ)

- **accounts/** — служба аккаунтов ОТДЕЛЬНО от мира: пользователи, вход, токены (HMAC),
  привязка user→персонаж. Про мир не знает. Единая регистрация для любых клиентов.
- **server/ + wsrv/** — HTTP (register/login) + WebSocket (RFC 6455 на stdlib). Мир крутится
  в горутине; игрок по токену вселяется в тело, отключился — телом правит AI (лестница присутствия).
- протокол JSON: клиент шлёт намерения (`{op,goal}`), сервер — картину вокруг персонажа.
  Тот же протокол подключит Unity — движок меняется, мир не трогаем.
- **thin-client/web** — мобильный веб-клиент: вход → вселение → состояние/деревня/соседи → цели.

## 10. Масштаб и оптимизация (раз язык Go)

Бенчмарк: **100 деревень, ~2000 сущностей (1163 души) — один час мира за 1.57 мс** (~640
тиков/с, ~26 игровых дней/с). Запас большой. Экономика ходит по людям за один проход.
Квадратичное место (скан жителей по деревням в LifeSystem) известно — при тысячах деревень
добавим индекс place→поселение и горячо/холодно (LoD): холодные регионы считаются дёшево,
но полными сущностями (память без потерь). Мир уже растёт САМ: новые поселения основываются
переселенцами из переполненных (procedural-топонимы), деревни растут в города.

## 11. Дорожная карта (обновлено)

1. ✅ Живое ядро (сущности-компоненты, разум, память без потерь, кости) — с тестами.
2. ✅ Экономика на законе сохранения (сезоны, угодья, цепочки, торговля, десятина).
3. ✅ Сетевой слой: аккаунты (отдельно) + websocket + тонкий веб-клиент — СЕРВЕР ЗАПУСКАЕТСЯ.
4. ✅ Рост мира: основание новых поселений, деревня→город; бенчмарк масштаба.
5. Большой мир: континенты/регионы-контейнеры, рельеф (реки/горы — уже гейтят угодья),
   карта мира; горячо/холодно (LoD) и индексы под тысячи поселений.
6. Перенос из прототипа поверх ядра: мини-игры, карты, путешествия, бой/тело, магия.
7. Экономика-2: деньги/цены рынка, межгосударственная торговля, войны за ресурс, налоги-события.
8. Квесты «от ума НПС»; события от решений.
9. worldmut (1.5): изменяемый мир (Red Faction/Rust) под будущую графику.
10. Unity-клиент (2.x): подключение к протоколу, рендер, установщик.

## 12. Как это запустить

```
cd 1-server
go test ./...                         # все тесты (ядро, экономика, аккаунты, сеть)
go run ./cmd/pogserver                # СЕРВЕР на :8090 → открой http://localhost:8090/
                                      #   регистрируешься и вселяешься в жителя мира
go run ./cmd/pogserver -demo -days 5910   # headless-прогон с «отчётом о жизни»
go test ./sim/ -run x -bench BenchmarkTick -benchmem   # бенчмарк масштаба
```
