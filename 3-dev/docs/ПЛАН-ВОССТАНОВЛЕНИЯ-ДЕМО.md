# План приведения «Пограничья» в норму — восстановление играбельного демо

Дата сводки: 2026-11-14  
Статус: рабочий backlog по жалобам владельца из предыдущих чатов.  
Принцип: это план исправления уже заявленных проблем, а не изменение концепции.

## 0. Неизменная архитектура

Пограничье — единая постоянная серверная симуляция живого мира. Go-сервер владеет миром, NPC, экономикой, временем, ресурсами, перемещением, сохранением и результатами действий. Unity и thin-client — окна в одну симуляцию: получают серверное состояние, отображают его и отправляют намерения. Не создавать локальный игровой мир или локальные authoritative NPC/предметы.

Два входа по ADR 0006 сохраняются: Demo/Starter Cauldron и Open World Start. Это два входа в одну симуляцию, а не две игры.

## 1. Критерий «игра приведена в норму»

Владелец должен суметь:
1. Запустить клиент без ошибок компиляции.
2. Войти в мир через предусмотренный стартовый режим.
3. Плавно ходить, смотреть мышью, бежать достаточно долго; не терять управление в диалогах и меню.
4. Встретить работающих NPC, понять их деятельность, поговорить с ними и получить/выполнить простое поручение.
5. Взаимодействовать с предметами и точками интереса без случайных промахов и стен, перекрывающих выбор.
6. Увидеть убедительное поселение: дома не перекрывают друг друга, масштаб деревенский, окружение не выглядит набором заглушек.
7. Войти в таверну, увидеть жителей, купить/взять кружку и выпить пиво с серверным подтверждением.
8. Открыть понятный инвентарь/рабочую сумку, видеть экипировку и предмет в руке.
9. Купить/оседлать лошадь там, где это разрешает сервер, и получить согласованное движение.
10. Пройти по дороге за пределы поселения и увидеть продолжающийся, связный мир, а не пустую плоскость до горизонта.
11. Видеть карту и знания о мире, соответствующие знаниям персонажа, с масштабированием и туманом неизвестного.
12. Сохранить диагностический дамп и приложить его для разбора.

Демо не считается готовым только потому, что код смержен: нужны проверки в Unity и сквозные проверки с работающим сервером.

## 2. P0 — блокирует базовую играбельность (делать в первую очередь)

### P0.1 Вход, сборка и устойчивость клиента
- Проверить чистый импорт проекта в Unity 6000.6.7f1, URP и Input System.
- Устранить compile/runtime regressions после новых ассетов и скриптов.
- Проверить стартовую сцену, авторизацию, подключение WS, повторное подключение и terminal `alive:false`.
- Разделить compile, Editor, PlayMode и серверные проверки; не объявлять всё проверенным по одному успешному входу.
- Проверить новую систему диагностических дампов F3: файл, валидный JSON, ограничения размера/ротации, отсутствие credentials/chat/voice.

**Владелец:** ChatGPT — клиент; владелец — Unity smoke test.

### P0.2 Передвижение и камера
Жалобы владельца (10–11 ноября): мышь слишком чувствительная; спринт заканчивается слишком быстро; управление и взаимодействия после изменений стали хуже.
- Перепроверить уже внесённые изменения (в истории упоминался PR #250: чувствительность 0.075→0.035, спринт примерно 5.5→10 секунд, исправления домов и луча взаимодействия); не считать их принятыми без runtime проверки.
- Настроить чувствительность отдельно по горизонтали/вертикали, проверить инверсию/пределы и отсутствие рывков.
- Проверить длительность/скорость спринта и восстановление выносливости по серверному состоянию.
- Проверить блокировки ввода при диалоге, меню, карте, магическом плетении и мини-играх.
- Сохранить обычный mouse look; RMB оставить для альтернативных режимов, а не обязательного движения.
- Проверить пешие переходы между поселениями: клиент не должен сам телепортировать игрока или подменять серверную позицию.

**Владелец:** ChatGPT; серверная выносливость/перемещение — Claude.

### P0.3 Взаимодействия и диалоги
Жалоба владельца: взаимодействие с NPC/активностями стало хуже; диалоги нужны крупнее и с выбором кнопками.
- Стабилизировать прицел/selection ray: стены и коллайдеры домов не должны перехватывать интеракцию; дистанция и видимость должны быть ясны.
- Проверить NPC talk, POI, двери, market, stable, tavern и activities end-to-end.
- Сделать реплики/варианты крупными и читаемыми, варианты — отдельными кнопками.
- Не показывать успех локально до server result.
- Отображать причины отказа сервера понятным текстом и не терять их из-за быстрого следующего результата.
- Имена NPC показывать с учётом знания/знакомства персонажа, не раскрывать неизвестных.

**Владелец:** ChatGPT — интерфейс/ввод; Claude — серверные действия/результаты.

### P0.4 Поселение и коллизии
Жалобы владельца: дома наложились друг на друга, были слишком большими и не похожими на деревенские.
- Проверить планировки на нескольких seed и поселениях, а не только стартовую сцену.
- Визуальный footprint дома должен соответствовать серверному footprint/POI; здания не пересекаются, двери и улицы доступны.
- Развести визуальные меши, коллайдеры и raycast layers.
- Сохранить процедурные декорации как визуализацию; они не должны создавать серверные POI/ресурсы/проходимость.
- Проверить плотность и масштаб: деревня, а не крупные дома, случайно наложенные друг на друга.

**Владелец:** ChatGPT — Unity projection; Claude — layout/POI/валидность серверной геометрии, если нарушен контракт.

### P0.5 NPC и жизнь поселения
Жалобы/наблюдения из предыдущих разборов: NPC шли напрямую к цели с axis-slide и застревали; после серверных исправлений оставались congestion/stuck recovery; таверна была пустой.
- Проверить, что жители физически перемещаются по проходимым маршрутам, обходят здания и не проходят сквозь препятствия.
- Дороги/тропы должны участвовать в навигации; нужен серверный waypoint/path graph или согласованный эквивалент, а не независимое движение по прямой.
- Проверить congestion, застревание и recovery без телепортаций, нарушающих наблюдаемое движение.
- Проверить разнообразие server act_code и корректную клиентскую анимацию/позу по act_code, а не по свободному тексту goal.
- Проверить населённость улиц и таверны по серверному расписанию/целям; не создавать NPC локально ради заполнения кадра.
- Проверить стабильность идентификаторов, AOI вход/выход, отсутствие скачков/дубликатов.

**Владелец:** Claude — симуляция/navigation/AOI; ChatGPT — entity views/анимации.

### P0.6 Таверна, пиво и совместные действия
Жалобы владельца: таверна была пустой; пиво должно покупаться у стойки/корчмаря, питьё должно быть реальным серверным действием; цель — пить вместе с другим игроком.
- Сквозной сценарий: подойти к стойке → получить доступное предложение → купить/получить кружку → consume → сервер подтверждает изменение состояния и расход запасов.
- Проверить цену, конечный stock, reqid/idempotency и повторные запросы.
- Не давать клиенту рисовать полную кружку/успех при неуспешном серверном результате.
- Проверить посадку/места и социальное поведение NPC, чтобы таверна не была пустой без причины.
- Отдельно проверить совместное питьё двух реальных сетевых игроков; не подменять его локальной анимацией.

**Владелец:** Claude — экономика/социальная симуляция/контракт; ChatGPT — стойка, кружка, анимация и UI.

### P0.7 Мир не должен обрываться в пустоту
Жалоба владельца (11 ноября): при уходе далеко в одну сторону видел пустую землю до горизонта; требование — бесшовный мир.
- Сквозной тест физического движения в каждом направлении через границы 256m chunks и регионов.
- Подтвердить открытие frontier от реального перемещения, сохранение открытых регионов и отсутствие обязательного teleport `op:travel` как единственного перехода между физически соседними местами.
- Проверить непрерывность terrain height/mesh/collider на стыках чанков.
- Нужны серверные descriptors для биомов, воды/рек, лесов/растительности, полей, дорог/троп, ресурсов, диких мест и точек интереса.
- Unity только стримит и визуализирует серверные descriptors/seed; не придумывает проходимость, POI и ресурсы.
- Проверить дальний туман и переход видимости, чтобы масштаб мира ощущался большим, но не скрывал отсутствие генерации.
- Проверить сетевую подгрузку чанков, отмену старых запросов, кэш/retention и отсутствие дыр/мигания.

**Владелец:** Claude — world generation/frontier/server streaming contract; ChatGPT — Unity terrain/environment streaming.

## 3. P1 — делает демо понятным и убедительным

### P1.1 Инвентарь, рабочая сумка и экипировка
Жалобы владельца: инвентарь должен быть логичным и рабочим, с концепцией сумки; предметы должны быть видны в руках.
- Разделить «при себе», рабочую сумку, седельные сумки/хранилище, сундук/склад и надетые вещи так, как задаёт сервер.
- Показывать вместимость/нагрузку и ограничения переноски; не создавать локальные предметы.
- Понятные категории, подписи, количество, контекстные действия и причины отказа.
- Реально отображать server `inv.hand` и `inv.worn` на персонаже/NPC; не ограничиваться текстом.
- Проверить перенос/экипировку/снятие/передачу предметов сквозным путём.

**Владелец:** ChatGPT — UI/visuals; Claude — инвентарь, веса/ёмкости и операции.

### P1.2 Лошадь и конюшня
Жалоба владельца: лошади не работали.
- Сквозной тест: серверная доступность/запас конюшни → покупка → появление HorseC → mount/dismount → движение и скорость → stamina/корм → stash/unstash.
- Проверить reqid, idempotency, условия POI и читаемые ошибки.
- Клиент показывает только серверную лошадь и подтверждённое состояние всадника.
- Предметы экипировки/седло/сумки отображаются на правильной сущности.

**Владелец:** Claude — сущности и правила; ChatGPT — визуализация/управление/индикация.

### P1.3 Карта, навигация и знания персонажа
Пожелания владельца (10–11 ноября): отдельные карты поселений, общая карта, масштабирование, пешее путешествие по сети дорог и большой мир, скрытый туманом.
- Разделить developer/streaming manifest и карту знаний персонажа.
- Не показывать неизвестные дороги/поселения как будто персонаж их знает.
- Карта строится из серверных знаний: слухи/обнаружено/посещено/известно (актуальная модель сервера).
- Добавить zoom/pan, уровень детализации и переход «карта мира ↔ карта поселения».
- Маршрут пешком должен быть связан с реальными дорогами/переходами; не обещать маршрут, который сервер не может пройти.
- Туман неизвестного — визуализация knowledge state, не локальная генерация открытия.

**Владелец:** Claude — knowledge/map data; ChatGPT — карта/UI/projection.

### P1.4 Визуальное качество и читаемость
Жалобы владельца: нужны нормальные модели, текстуры, меши, анимации, дальний туман и разнообразные локации; ранний прототип выглядит сыро.
- Убрать очевидные placeholder-цилиндры/примитивы там, где они воспринимаются как основные игровые предметы (особенно кружки, инструменты, предметы в руках).
- Проверить импорт бесплатных ассетов, лицензии, URP materials/shaders, масштабы, pivot, LOD и colliders.
- Улучшить деревья/трава/земля/камни/вода/дома и разнообразие поселений без нарушения server geometry.
- Исправить знаки: не просвечивают сквозь стены и не читаются с чрезмерной дистанции; корректный размер, ориентация и occlusion.
- Шрифты/диалоги/инвентарь должны быть читаемы в реальном разрешении пользователя; технические подсказки не должны перегружать экран.
- Нужны предметы в руках, анимации мини-игр, базовые locomotion/interaction animations и правдоподобные NPC poses.
- Дальний туман/небо/погода должны поддерживать ощущение большой территории.

**Владелец:** ChatGPT — Unity presentation/assets; владелец — импорт/проверка Blender/Unity.

### P1.5 Мини-игры и социальное присутствие
- Анимации и визуальная обратная связь мини-игр; клавиатурное управление и фокус не должны ломать основной input.
- Проверить карточную игру в таверне и её сетевую авторитетность.
- Игроки и NPC должны видеть согласованное состояние действий/поз.
- Не воспроизводить локально исход мини-игры до подтверждения сервера.

**Владелец:** Claude — правила/состояние; ChatGPT — input/UI/анимации.

## 4. P2 — расширение после устойчивого демо

- Больше разнообразия регионов, деревень, городов, лесов, полей, рек, бандитских баз и мест силы.
- Долгие пешие путешествия, погода/сезоны, дальние ориентиры и постепенно открываемые холодные страны.
- Больше систем выживания и бытовой симуляции в духе Outward, но только после надёжного базового цикла.
- Тонкая версия для телефона/браузера должна управлять тем же персонажем и тем же серверным миром.
- Производительность больших популяций: spatial AOI/index, hysteresis, stable IDs/tombstones, bounded client views; не решать масштабирование простым увеличением лимитов.

## 5. Известные исторические технические риски — перепроверить, не считать текущими без воспроизведения

- NPC waypoint graph отсутствовал/не использовался клиентом; движение по прямой приводило к застреванию.
- После серверных merge оставались congestion/stuck recovery.
- `me.result` хранит только последний результат: быстрые последовательные действия могут терять сообщения результата; требуется проверить sequence/feed correlation.
- Persistence обучения/прогресса обсуждалась как отсутствующая — подтвердить текущий статус.
- В `Assets/Resources/TavernProps` не было авторских FBX, из-за чего использовались процедурные модели.
- После импорта ассетов сообщалось об ошибках Input System, ProceduralGait, вызове `Transform.SetActive`, TypeLoadException InputActionAsset, устаревших .meta, самопересекающемся terrain mesh и неверном shader травы. Проверить чистый импорт и актуальность исправлений.
- Пользователь ранее сообщал о проблемах шрифтов, инвентаря, знаков, пустой таверне, отсутствии товаров на рынке и неработающей лошади; считать закрытыми только после повторного E2E теста.

## 6. Порядок работ и Definition of Done

1. Сначала P0: стабильный вход, управление, взаимодействия, деревня, NPC, таверна, физическое движение в непрерывном мире.
2. Затем P1: инвентарь/экипировка, лошадь, карта/знания, визуальная полировка и мини-игры.
3. P2 — после того, как первый игровой цикл действительно проходит от входа до путешествия и возвращения.

Каждый пункт получает отдельный task-файл с владельцем и критериями. Статусы:
- `!В работе` — выполняется;
- `!Блокировано` — указана причина;
- `!Выполнено` — только после фактической проверки.

Для каждого E2E сценария фиксировать: клиентский дамп, server logs/test, ожидаемое подтверждение, фактический результат. Не выдавать source-level merge за runtime completion.

## 7. Проверочные сценарии демо (release gate)

- Clean launch → login → selected start mode → authoritative frame.
- Move/look/sprint → server position reconciliation.
- NPC encounter → talk → button choice → server result.
- Activity/errand → completion → feed/result update.
- Enter tavern → see residents → beer transaction → consume.
- Two connected players → see each other → shared tavern interaction.
- Inventory/equipment → visible hand/worn state.
- Stable → horse purchase → mount → ride → dismount.
- Walk over multiple chunk boundaries and through a frontier transition in all directions.
- Reopen map: only character-known geography is shown.
- Save F3 diagnostic dump and correlate one client request with server logs.
