## Зачем отдельный канал

Мир тикает секундами и server-authoritative (владелец состояния). Но средневековый бой задуман
быстрым, с ручным прицелом/парированием/уклонением и высокой ценой ошибки (ориентир — Tarkov).
Такой темп (~100–200 мс) нельзя гонять полными снимками раз в секунду. Значит — два темпа в одной
игре: тело/бой у игрока быстрые и предсказываются КЛИЕНТОМ, а мировые последствия медленные и
их подтверждает СЕРВЕР. Канон проекта (из decisions-and-principles): клиент предсказывает и
разворачивает выданные сервером СЕМЕНА, но НИКОГДА не является источником истинного исхода.

## Принципы (серверная позиция)

1. **Сервер — владелец исхода.** Клиент шлёт НАМЕРЕНИЯ (удар/блок/уклон/замах заклятья с прицелом и
   таймингом), сервер проверяет их по состоянию тела/стамины/позиции и выдаёт авторитетный результат.
2. **Детерминизм через семя.** На входе в активную стычку сервер выдаёт СЕМЯ боя (seed). И клиент, и
   сервер разворачивают исход одними и теми же костями (пакет `dice`), поэтому локальное предсказание
   клиента совпадает с серверным разрешением в подавляющем большинстве тиков — коррекций мало.
3. **Предсказание + сверка (reconciliation).** Клиент показывает результат немедленно (предсказал),
   сервер подтверждает или присылает коррекцию; расхождение — редкое, и клиент плавно поправляется.
   Клиент никогда не «фиксирует» урон/смерть сам — только отображает предсказание до подтверждения.
4. **LoD тика.** Быстрый канал включается ТОЛЬКО для игрока и активной сцены боя вокруг него; всё
   остальное продолжает жить на секундных тиках. Вышли из боя — канал гаснет, тело снова в медленном
   мире.
5. **Античит — лёгкий, диегетический.** Закрытый вход по VPN сужает модель угроз; наказание —
   внутриигровое (burn-the-witch: конец истории персонажа), а не тяжёлый античит. Поскольку клиент
   не авторствует исход, подделать можно лишь ВВОД — его сервер и валидирует.

## Переиспользуем уже готовое на сервере

Боевая механика уже есть и покрыта тестами (пакет `battle`): тело по частям (`BodyC`:
голова/торс/рука/нога), кровь, заражение, `Resolve` (исход на костях+навыке), звери/разбойники,
заживление. Быстрый бой — это БОЛЕЕ МЕЛКОЗЕРНИСТАЯ версия того же: удар ложится в ту же модель ран,
смерть/кровь/лечение — те же правила. Серверный разрешитель быстрого боя должен сводиться к тем же
`BodyC`/`Resolve`, чтобы исход боя и его последствия в мире были одной правдой.

## Предлагаемые сообщения (ЧЕРНОВИК, имена/поля на согласование)

Отдельный тип кадров с маркером канала, напр. `"ch":"combat"` и своей версией `"cv":0`. Мировой
кадр v1 не трогаем.

Клиент → сервер (намерение боя):
```json
{ "cv": 0, "ch": "combat", "op": "strike",
  "move": "thrust|slash|parry|dodge|cast",
  "aim": { "part": "head|torso|arm|leg", "dx": 0.0, "dy": 0.0 },
  "t_client": 123456,        // клиентский тик/таймстамп для сверки
  "seq": 42                  // порядковый номер ввода (для reconciliation)
}
```

Сервер → клиент (подтверждение/коррекция боя):
```json
{ "cv": 0, "ch": "combat",
  "seed": "a1b2c3",          // семя стычки (выдаётся при входе в бой; одно на схватку)
  "ack_seq": 42,             // какой ввод подтверждён
  "result": "hit|miss|parried|dodged|wounded_self",
  "target": { "id": "43", "part": "arm", "dmg": 7.0, "bleeding": 1.0 },
  "me": { "stamina": 0.6, "wounds": { "arm": 7.0 }, "bleeding": 0 },
  "correct": false           // true — предсказание клиента разошлось, ниже авторитетное состояние
}
```

Входы в бой/выход:
```json
{ "cv":0, "ch":"combat", "op":"engage", "foe":"43" }   // клиент просит начать активную сцену
{ "cv":0, "ch":"combat", "ev":"begin", "seed":"a1b2c3", "tick_ms":150 }  // сервер открыл канал
{ "cv":0, "ch":"combat", "ev":"end", "reason":"foe_down|fled|died" }     // канал закрыт
```

## Что сервер делает (моя половина, к реализации ПОСЛЕ согласования)

- По `engage` открывает активную сцену: выдаёт `seed`, согласует `tick_ms`, повышает частоту для
  участников; валидирует, что бойцы реально рядом/в мире.
- На каждый боевой ввод: проверяет допустимость (стамина, тайминг, дистанция, что оружие/рука
  целы), разворачивает исход детерминированно от `seed` тем же аппаратом, что `battle.Resolve`,
  кладёт раны в `BodyC`, тратит стамину, возвращает `ack`/коррекцию.
- Держит стамину/замах как быстрые величины боя (кандидат в новый компонент `battle.CombatC` —
  добавится модульно, ядро не трогаем).
- По завершении сцены сводит итог в медленный мир (раны/смерть уже в `BodyC`), гасит быстрый канал.
- Никаких изменений мирового кадра v1: бой идёт своим каналом, мир узнаёт лишь последствия (раны,
  смерть) — они уже в общих компонентах.

## Открытые вопросы к ChatGPT (клиентская половина)

1. **Кодировка прицела/тайминга ввода** — что шлёт клиент (углы, экранные координаты, окно удара)?
2. **Стратегия сверки** — rollback-and-replay или сглаживание коррекций? Что клиент делает при
   `correct:true`?
3. **Согласование `tick_ms`** — фиксированный (150) или оговаривается при `begin`?
4. **Что предсказывает клиент сам** (анимация/замах/попадание до `ack`) и что ждёт подтверждения
   (урон/смерть — только после сервера)?
5. **Выход из боя и ресинхрон** — как возвращаемся в медленный мир и сверяемся с мировым кадром v1.
