# Быстрый старт на виртуалке (через Git + скрипт)

Теперь код живёт в Git: `https://github.com/IskatelApelsinov/pogranichye`.
Обновление и запуск автоматизированы скриптом `manage.sh` — вручную команды docker
набирать не нужно.

## Первый раз на ВМ
```bash
# 1. поставить git (если ещё нет)
sudo apt-get update && sudo apt-get install -y git

# 2. склонировать репозиторий
git clone https://github.com/IskatelApelsinov/pogranichye.git
cd pogranichye

# 3. поставить Docker (один раз; после — перелогиниться или 'newgrp docker')
./manage.sh install-docker

# 4. запустить сервер в DEV-режиме (гостевой вход — нужен для толстого клиента)
./manage.sh dev
```
После этого:
- тонкий клиент — браузер `http://localhost:8090`
- наблюдатель мира — `http://localhost:8090/observe`
- толстый 3D-клиент — Godot, проект `godot3d-client/` (адрес сервера в узле **Main**)

> Порт/пароль БД/режим настраиваются в файле `.env` (создаётся скриптом). При NAT в
> VirtualBox проброс порта должен совпадать с `APP_PORT` (по умолчанию 8090).

## Каждый день / после моих правок
```bash
cd pogranichye
./manage.sh update      # git pull + пересборка + перезапуск (режим сохраняется)
```

## Команды скрипта
| Команда | Что делает |
|---|---|
| `./manage.sh dev` | запустить в DEV (гость включён — для толстого клиента) |
| `./manage.sh prod` | запустить в PROD (вход только по аккаунту) |
| `./manage.sh update` | обновить из git и перезапустить |
| `./manage.sh stop` | остановить (БД сохраняется) |
| `./manage.sh reset` | стереть БД мира и поднять заново (dev) |
| `./manage.sh logs` | смотреть логи сервера |
| `./manage.sh status` | статус контейнеров и адрес |
| `./manage.sh install-docker` | поставить Docker (один раз) |

## Режимы: чем отличаются
- **dev** — доступен гостевой вход без регистрации. Нужен, чтобы заходил толстый
  3D-клиент (он логинится гостем). Удобно для тестов.
- **prod** — гость выключен, вход по зарегистрированному аккаунту. «Боевой» режим.

## Если что-то не поднялось
```bash
./manage.sh status           # контейнеры: Up или Restarting?
./manage.sh logs             # трейсбэк приложения (частая причина — БД)
```
Рассинхрон пароля БД со старым томом лечится `./manage.sh reset` (стирает мир)
или возвратом прежнего `DB_PASSWORD` в `.env`.
