# Интеграция «Приграничья» в реальный сервер (прод) — задание для отдельной беседы

Этот документ — вводная для нового чата, где будем выносить игру с тестовой
виртуалки на боевой сервер с доменом и TLS. Здесь контекст, архитектура сети и
чек-лист. Код игры уже контейнеризирован (Docker) и лежит в git:
`https://github.com/IskatelApelsinov/pogranichye`.

## Что уже есть
- **Сервер игры** — Python stdlib + psycopg2, слушает HTTP и **WebSocket** на одном
  порту (по умолчанию 8090). WS — несущий протокол (состояние мира пушится дельтами),
  поэтому реверс-прокси обязан корректно проксировать Upgrade/WebSocket.
- **Docker Compose**: сервис `app` (игра) + `db` (PostgreSQL 16), том `pgdata`.
- **Режимы**: `GAME_ENV=dev|prod` (prod — без гостевого входа), `GAME_SECURE=0|1`
  (1 — когда за HTTPS/реверс-прокси: защищённые cookie), `APP_PORT`, `DB_PASSWORD`,
  `DATABASE_URL`.
- Клиенты: тонкий (браузер, та же точка входа), наблюдатель `/observe`,
  толстый 3D (Godot, подключается к `ws(s)://host/ws`).

## Цель прод-интеграции
Поднять игру на реальном сервере так, чтобы:
1. открывалась по домену по HTTPS (например `https://pogranichye.example.ru`);
2. WebSocket работал через тот же домен по WSS (TLS);
3. был автозапуск и перезапуск при падении/перезагрузке;
4. были базовые безопасность и резервные копии БД.

## Архитектура сети (рекомендуемая)
```
Игрок ──HTTPS/WSS──> [реверс-прокси: Caddy или nginx, TLS Let's Encrypt]
                         │  проксирует / и /ws (с Upgrade) на 127.0.0.1:8090
                         ▼
                   [app (docker)]  ── 5432 ──> [db (docker, pgdata)]
```
- Порт 8090 наружу НЕ открывать — только реверс-прокси (443) смотрит в интернет.
- В compose для `app` можно сменить проброс на `127.0.0.1:8090:8090` (только локально).
- Выставить `GAME_SECURE=1` и `GAME_ENV=prod`.

## Чек-лист для нового чата
1. **Домен и DNS**: A-запись на IP сервера.
2. **Реверс-прокси + TLS**:
   - Caddy — проще всего (автоTLS). Пример для Caddy:
     ```
     pogranichye.example.ru {
         reverse_proxy 127.0.0.1:8090
     }
     ```
     Caddy сам проксирует WebSocket (Upgrade) — отдельной настройки обычно не нужно.
   - Либо nginx + certbot; для nginx ОБЯЗАТЕЛЬНО добавить проксирование WS:
     ```
     location / {
         proxy_pass http://127.0.0.1:8090;
         proxy_http_version 1.1;
         proxy_set_header Upgrade $http_upgrade;
         proxy_set_header Connection "upgrade";
         proxy_set_header Host $host;
         proxy_read_timeout 3600s;   # WS держится долго
     }
     ```
3. **compose под прод**: `GAME_ENV=prod`, `GAME_SECURE=1`, проброс `127.0.0.1:8090:8090`,
   сильный `DB_PASSWORD` (не из примера), том `pgdata` на диске с бэкапом.
4. **Автозапуск**: `restart: unless-stopped` уже есть; добавить, чтобы Docker
   стартовал при загрузке (`systemctl enable docker`). Можно обернуть в systemd-unit.
5. **Фаервол**: открыть только 443 (и 22 для SSH), закрыть 8090/5432 снаружи (ufw).
6. **Клиент (толстый 3D)**: переключить на `wss://домен/ws` (сейчас `ws://host:port`).
   Понадобится правка в `godot3d-client/Main.gd` (схема wss и без порта) — учесть.
7. **Бэкапы БД**: периодический `pg_dump` из контейнера `db` в файл + ротация.
8. **Безопасность**: не коммитить `.env` с паролями (уже в .gitignore — проверить),
   ограничить SSH по ключу, обновления ОС, при желании — rate-limit на прокси.
9. **Мониторинг**: healthcheck уже есть (`/healthz`); можно повесить внешний пинг.

## Важные нюансы, о которых помнить
- **WebSocket через прокси** — главная точка отказа. Если WS не проксируется с
  Upgrade, тонкий и толстый клиенты не подключатся (симптом: HTTP открывается,
  а игра «висит на подключении»).
- **GAME_SECURE=1** нужен только когда реально за HTTPS — иначе cookie с флагом
  Secure не долетит по HTTP, и вход сломается.
- **Миграция мира**: смена генерации (число деревень и т.п.) применяется к НОВОМУ
  миру. Перенос боевой БД — отдельная тема (pg_dump/restore).
- Текущий сервер однопроцессный (по потоку на WS-соединение). Для больших нагрузок
  обсудить горизонтальное масштабирование отдельно (это нетривиально из-за общего
  состояния мира — сейчас мир в памяти одного процесса).

## С чего начать в новом чате
Скажи: «интегрируем Приграничье в прод по ПРОД-ИНТЕГРАЦИЯ.md», дай доступ к серверу
(или опиши, какой у тебя: ОС, есть ли домен, панель/без панели), и выберем Caddy или
nginx. Дальше пошагово: прокси+TLS → прод-compose → фаервол → клиент на wss → бэкапы.
